# 도구 설명이 토큰을 먹고 있었다

Discord로 일을 시키는 개인 Agent를 운영하다 보니, "1달러는 몇 센트야?" 같은 짧은 질문에도 모델 입력이 3천 토큰을 넘었다. 요금이 따로 나가지 않는 구독 모델을 쓰지만 사용 한도는 정해져 있어서 한도를 어디에 쓰고 있는지부터 알아야 했다.

## 무엇이 입력을 채우고 있었나

요청 하나를 처리할 때 모델에는 사용자 문장만 가는 게 아니다. 시스템 지시문과 Agent가 쓸 수 있는 도구 24개의 설명이 매번 함께 간다. 토크나이저(`o200k_base`)로 세어 보니 도구 설명이 2,371토큰, 지시문이 840토큰이었고 사용자 문장은 평균 13토큰이었다. 입력의 대부분은 요청과 상관없이 매번 똑같이 붙는 도구 설명이었다.

그래서 질문을 바꿨다. 모델을 더 싸게 쓰는 방법보다, 이 요청에 필요 없는 내용을 보내지 않는 방법을 먼저 찾기로 했다.

## 측정 방법

비교 기준이 흔들리지 않도록 실제로 쓸 요청 20개를 유형별로 고정했다. 단순 질문, 예약 같은 고정 명령, 도구 하나로 끝나는 요청, 여러 단계 요청, 앱 조작 요청이다. 도구는 운영 코드의 이름과 입력 형식을 그대로 쓰고 결과만 가짜로 돌려주게 해서 실험 중에 메시지가 실제로 나가지 않게 했다.

처음에는 실제 모델을 부르며 비교하려 했지만 방향을 바꿨다. 구독 모델을 실험 목적으로 수백 번 자동 호출하는 방식은 일반 사용 범위를 벗어날 수 있었다. 그래서 모델을 부르지 않고 토크나이저로 입력 크기만 계산하는 오프라인 측정으로 좁혔다.

## 세 가지를 차례로 적용했다

먼저 요청에 필요한 도구 묶음만 코드가 골라 보내게 했다. "경로"가 있으면 길찾기 도구를, "메일"이 있으면 메일 도구를 넣고, 아무 단어도 안 걸리면 도구를 하나도 보내지 않는다. 이것만으로 호출 1회당 입력이 64,474토큰에서 23,792토큰으로 63% 줄었다.

다음으로 도구 설명을 첫 문장만 남겨 봤는데, 추가 절감은 2%p였다. 설명이 짧아지면 모델이 도구를 잘못 고를 위험이 있어서 이득에 비해 위험이 크다고 보고 우선순위를 내렸다.

마지막으로 정해진 문장 형태는 코드가 바로 처리하게 했다. "10분 뒤에 빨래 꺼내라고 알려줘"는 정규식으로 시간과 내용을 잘라 예약 도구를 바로 실행한다. 표현만 다른 같은 질문은 저장해 둔 답을 다시 쓴다. 20개 중 9개가 모델 없이 끝났고 합계는 12,693토큰으로 기준보다 80% 적었다.

## 틀린 지점

도구 고르기 첫 버전은 "알려줘"만 들어 있어도 예약 도구를 붙였다. 그러자 "파이썬 리스트 뒤집는 방법 알려줘"라는 단순 질문에 예약 도구가 따라붙어 테스트가 실패했다. 한국어 요청에서 "알려줘"는 예약보다 질문에 훨씬 자주 쓰인다. 예약으로 판단하려면 "10분 뒤", "알림" 같은 시간 표현이 있어야 하도록 조건을 좁혔다.

## 아직 모르는 것

이번 숫자는 호출 1회당 입력만 셌다. 실제 요청은 모델을 여러 번 부르고 도구 결과도 입력에 쌓이기 때문에, 실제 절감 비율은 다르게 나올 수 있다. 요청 세트도 직접 만들었으니 라우터가 처리한 9개라는 수치는 낙관적이다. 도구를 골라 보내다 필요한 도구를 빠뜨리면 모델이 일을 못 하므로, 그때 전체 도구로 다시 시도하는 장치와 그 비용도 따로 재야 한다. 다음 단계는 운영 Agent에 적용한 뒤 실제 응답에 기록되는 토큰으로 적용 전후를 비교하는 것이다.

## 셀프 인터뷰

**왜 모델 교체가 아니라 입력 줄이기부터 봤나요?**
측정해 보니 입력의 대부분이 요청과 무관한 도구 설명이었습니다. 모델을 바꿔도 이 구조는 그대로라서 구조부터 고치는 쪽이 효과가 컸습니다.

**실제 모델로 실험하지 않은 이유는요?**
구독 모델을 실험 목적으로 대량 자동 호출하면 일반 사용 범위를 벗어날 수 있었습니다. 대신 모델 없이 계산할 수 있는 입력 크기와, 모델 없이 처리되는 요청 수를 쟀습니다. 결과 품질은 운영 기록으로 확인할 계획입니다.

**도구 설명을 줄이는 건 왜 미뤘나요?**
2%p 절감에 비해 모델이 도구를 잘못 고를 위험이 컸습니다. 효과가 크고 위험이 작은 방법부터 적용하는 게 맞다고 봤습니다.

**가장 크게 배운 점은요?**
감으로 고치지 않고 고정된 요청 세트로 한 번에 하나씩 바꾸며 재야, 무엇이 효과가 있었는지 설명할 수 있다는 점입니다. "알려줘" 오분류도 테스트를 먼저 만들어 둔 덕분에 바로 잡혔습니다.
