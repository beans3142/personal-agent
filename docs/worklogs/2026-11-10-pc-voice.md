# PC에서 "대비스, ..."라고 말하면 답을 소리로 듣는다

> 2026-11-10 · 커밋은 아래 산출물 참고 · 합성 음성 4문장 중 4문장의 호출어·명령을 맞게 인식, 잡음 20건 중 오작동 0건

## 무엇이 문제였나

소유자는 빅스비처럼 PC 앞에서 "대비스"라고 불러 대비스를 쓰고 싶어 했다. 계산과 명령은 서버를 거쳐야 하지만, 대비스 본체 서버는 쉬면 꺼지도록 되어 있다. 소유자는 본체 서버를 "필요할 때만 켜는" 방식을 골랐다.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| 음성을 서버로 보내 인식 | PC 쪽이 단순하다 | 지연이 크고 PC 주변 소리가 밖으로 나가서 버림 |
| PC GPU에서 Whisper로 호출어와 명령을 함께 인식 | 가입이 필요 없고, 한국어 호출어가 되며, 3초 음성 인식에 0.15초 | 고름 |
| Porcupine 호출어 엔진 | 전력 소모가 가장 적다 | 계정 가입과 호출어 등록이 필요해서 보류 |
| 본체 서버가 PC에 직접 접속 | 경로가 짧다 | 서버가 꺼져 있을 수 있고 PC로 들어오는 포트를 열어야 해서 버림 |

## 바꾼 것

- PC 프로그램 `deploy/voice-pc.py`:
  - 소리 크기로 말 덩어리를 자른다.
  - faster-whisper medium(GPU)으로 글자로 바꾼다.
  - "대비스/데비스/다비스/자비스"로 시작할 때만 반응한다.
  - 명령 글자만 기존 PC 노드 인증으로 중계 서버에 보낸다. 답은 Windows 한국어 음성(Heami)으로 읽는다.
  - 호출어가 아닌 말은 기록하지도, 보내지도 않는다.
  - 오인식 방지: Whisper가 스스로 말이 아니라고 판단한 구간은 버린다. 인식 힌트 문장을 그대로 다시 말한 결과(잡음에서 생기는 환각)도 무시한다.
- 중계(전원 봇, `agent/voice_relay.py`):
  - 내부 노드 `voice`가 요청을 받는다. 등록된 PC에는 이 노드로 `voice_command`만 보낼 수 있는 권한을 준다.
  - PC 끄기, 폰 전화, 서버 전원 같은 규칙 명령은 그 자리에서 실행한다.
  - 나머지 요청은 본체가 꺼져 있으면 켜고 "서버를 켜고 있어요"를 먼저 말하게 한 뒤, 본체 노드 `agent-main`에 넘긴다.
- 본체(`agent/voice_agent.py`):
  - 게이트웨이가 2초마다 중계를 확인한다.
  - 소유자 DM 요청과 똑같이 처리해서 전문은 DM으로 보내고, 소리로 읽을 짧은 답(`agent/speech.py`)만 돌려준다.
- 노드 토큰 처리: 본체 노드 토큰은 PC에서 만들었다. 중계 서버에는 해시만 넣고, 토큰은 본체 `.env`에만 저장했다.
- 설치: `deploy/install-voice.ps1`. 패키지 설치, 프로그램 복사, 로그인 시 자동 실행 등록, 지금 실행을 한 번에 한다. 제거는 `-Uninstall`.

## 확인한 것

- 로컬 전체 테스트 798개가 통과했다. 음성 테스트 23개가 포함돼 있다.
- 이 PC에서 중계를 거쳐 본체까지 실제로 요청해 봤다. "지금 몇 시인지" 질문에 42.4초 만에 읽을 답이 돌아왔다. ChatGPT 사용량 한도 때문에 Claude로 처리된 결과다.
- Windows 한국어 합성 음성으로 4문장을 인식시켰다. 호출어와 명령을 모두 맞게 인식했고, 문장 중간에 "대비스"가 나온 경우는 무시했다.
  - 처음에는 "꺼줘"를 "거죠"로 인식했다. 인식 힌트에 명령 어휘를 넣어 고쳤다.
- 무음·백색잡음·저주파 웅웅거림·딸깍 소리 20건 중 호출어로 반응한 경우는 0건이었다.

## 아직 모르는 것

- 소유자의 실제 목소리와 방 소음에서의 인식률, 그리고 영상·음악 소리에 잘못 반응하지 않는지.
- 소리 크기 기준값(0.012)이 실제 마이크에 맞는지.
- 로그인 시 자동 실행: 이번 작업에서는 등록이 권한 정책에 막혀 실행하지 않았다. 소유자가 설치 스크립트를 직접 실행해야 한다.

## 셀프 인터뷰

1. **왜 호출어 전용 엔진 대신 Whisper를 계속 돌리나요?** 말소리가 있을 때만 인식하고 GPU에서 0.2초 안에 끝나기 때문입니다. 무엇보다 가입 없이 한국어 호출어를 바로 쓸 수 있습니다.
2. **본체가 꺼져 있을 때 얼마나 기다리나요?** 서버 부팅에 1~3분이 걸립니다. 그동안 "서버를 켜고 있어요"를 먼저 말해 줍니다. PC 끄기나 전화 같은 명령은 본체 없이 바로 처리됩니다.
3. **PC 주변 대화가 서버로 가나요?** 아닙니다. "대비스"로 시작한 문장의 명령 부분만 글자로 보내고, 나머지는 PC 안에서 버립니다.

## 이어서: PC 로그인 시 상시 실행, 폰은 Discord 음성 메시지로

- **데스크톱 상시 실행:** 소유자의 요청으로 `install-voice.ps1`을 실행했다. 로그인할 때 자동으로 실행되도록 등록했고, 지금도 실행 중이다.
  - 처음에는 소리 크기 기준값이 0.012였다. 이 PC의 USB 마이크 평소 소음은 0.0005 정도다. 스피커로 호출어를 틀어 시험했을 때 마이크에 잡힌 소리는 최대 0.0055였다. 그래서 기준값을 0.004로 낮췄다.
  - 이 PC는 스피커 소리가 마이크로 거의 들어가지 않는다(최대 0.0013). 그래서 사람 목소리로 시험하는 일은 소유자에게 남겼다.
  - 설치 스크립트를 UTF-8 BOM으로 저장했다. Windows PowerShell 5.1에서 한글 안내 문구가 깨지지 않게 하기 위해서다.
- **폰은 설치 없이 쓴다.** 대비스 DM에서 Discord 음성 메시지(마이크 버튼을 누르고 말하기)를 보내면 된다.
  - 본체가 음성을 faster-whisper small(CPU int8)로 글자로 바꾼 뒤, 입력한 글과 똑같이 처리한다.
  - PC·폰·서버 전원 명령은 본체가 중계를 거쳐 전원 봇에 넘긴다. 전원 봇은 음성을 직접 듣지 못하기 때문이다.
  - 본체가 꺼져 있을 때는 전원 봇이 음성 메시지를 보고 서버를 켠다. 본체는 켜진 뒤 최근 15분 안의 처리되지 않은 음성 메시지를 찾아 처리한다. 같은 메시지는 한 번만 처리한다.
  - 서버의 PyAV 19는 faster-whisper 기본 디코더가 넘기는 옵션(`metadata_errors`)을 지원하지 않는다. 그래서 디코딩을 직접 구현했다.
- **확인한 것:**
  - 로컬 전체 테스트 816개가 통과했다.
  - 서버에서 한국어 합성 음성 "엄마에게 카톡으로 오늘 늦는다고 보내줘"를 그대로 인식했다. wav는 8.2초(모델 첫 로드 포함), Discord 형식인 ogg/opus는 5.1초 걸렸다. 최대 메모리는 615MB였다.
  - 본체에서 중계를 거쳐 "서버 상태" 명령을 보냈다. 전원 봇이 처리해서 읽을 답을 돌려줬다.
- **아직 모르는 것:**
  - 실제 폰에서 보낸 음성 메시지와 실제 목소리로 인식이 되는지.
  - 서버 디스크 여유가 974MB(97%)뿐이다. Whisper 모델이 464MB를 차지한다.

## 이어서: 카톡 전송이 "보내지 못했습니다"로만 끝난 이유

- **증상:** 19:25에 채널에서 "동훈한테 뭐함이라고 카톡 보내줘"를 요청했다. 도구는 실행됐지만 답은 "메시지를 보내지 못했습니다." 한 줄이었다.
- **원인:** `data/kakao-direct-send.json`이 11월 8일 17:31부터 `pending` 상태로 남아 있었다. 그 시각에 시작한 전송이 말풍선 확인까지 가지 못한 것이다. 중복 전송을 막는 안전장치는 이 상태를 보면 이후 모든 전송을 거부하는데, 그 이유가 일반 오류로 바뀌어 사용자에게는 보이지 않았다.
- **바꾼 것:**
  - 잠긴 상태면 `KAKAO_BLOCKED`를 돌려준다. 답은 "이전 전송이 확인되지 않아 막았다, 카톡에서 확인한 뒤 '카톡 잠금 해제'라고 보내라"로 바뀐다.
  - `카톡 잠금 해제`는 모델 없이 처리한다. 전송 기록은 남기고 상태만 `reviewed`로 바꾼다.
  - 잠금은 자동으로 풀지 않는다. 그 메시지가 실제로 갔는지는 소유자만 확인할 수 있기 때문이다.
- **확인:** 로컬 전체 테스트가 통과했다(잠금 관련 테스트 5개 추가). 서버에 배포한 뒤 재시작했고 Discord 연결을 확인했다.
