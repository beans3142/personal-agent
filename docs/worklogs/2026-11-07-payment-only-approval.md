# 승인은 결제만, 요청한 채널에 버튼으로 받는다

> 2026-11-07 · 미커밋 · 휴대폰 검색 같은 일반 작업은 승인 없이 실행하고, 결제 버튼만 요청 채널에서 버튼으로 확인한다

## 무엇이 문제였나

채널에서 대비스를 태그해 쇼핑 앱 검색을 시켰다. 그런데 검색창에서 Enter를 누르는 단계에서 승인 요청이 왔고, 이 요청은 채널이 아니라 소유자 DM으로 갔다. 승인하려면 `승인 <16자리 코드>`를 120초 안에 직접 입력해야 했다. 아무도 입력하지 않아서 작업이 중단됐고, 소유자는 182초 동안 진행 상황을 보지 못했다.

## 왜 그런 일이 생겼나

- MCP 도구 서버는 읽기 전용 목록에 없는 도구를 모두 승인 대상으로 처리했다. 휴대폰 조작 도구는 일부만 예외였는데, 검색창 Enter를 누르는 `android_submit`이 그 예외 목록에서 빠져 있었다.
- MCP 서버는 Hermes 아래에서 도는 별도 프로세스다. 그래서 Discord 버튼 클릭 이벤트를 받을 수 없었다. 대신 REST API로 DM에 글을 쓰고 2초마다 DM 채널을 읽어서 답을 확인했다.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| `android_submit`만 예외 목록에 추가 | 한 줄 수정 | 승인 대상이 너무 넓다는 문제와 DM 문자 입력 방식이 그대로 남아서 버림 |
| 결제만 승인, 나머지는 소유자 요청이면 바로 실행 | 소유자가 원한 기준이고 승인 요청 수가 가장 적다 | 고름 |
| MCP 프로세스가 직접 Discord 버튼 처리 | 구조가 단순해 보인다 | 버튼 클릭 이벤트는 게이트웨이의 웹소켓 연결로만 들어와서 버림 |
| 요청별 작업 폴더에 승인 요청 파일을 쓰고 게이트웨이가 버튼을 띄움 | 스크린샷 전달에 이미 쓰는 공유 폴더를 재사용한다 | 고름 |

## 바꾼 것

- `agent/approvals.py` 추가
  - 결제 문구 판정(`PAYMENT`): 결제, 주문하기, 주문확정, 구매하기, Pay now, Buy now, Place order
  - 화면에 보이는 금액을 최대 3개까지 추출
  - 소유자 요청 정책: 결제가 아니면 바로 실행하고, 결제면 소유자에게 묻는다. 소유자 요청 권한(lease)이 없으면 아무것도 실행하지 않는다.
  - 파일로 주고받는 승인: `<outbox>/approvals/<id>.json`에 요청을 쓰고 `<id>.answer`를 기다린다. 대기 시간은 소유자 요청 권한이 끝나기 10초 전까지로 제한한다.
- `android_control.py`: 결제 버튼일 때만 승인을 묻는다. 삭제, 동의, 권한 허용, 로그아웃은 이제 묻지 않는다.
- `mcp_server.py`: DM 문자 입력 승인(`DiscordApproval`)을 삭제하고 위 정책으로 바꿨다.
- `gateway.py`: 요청을 처리하는 동안 승인 요청 파일을 확인한다. 요청이 있으면 그 채널에 앱 이름, 누를 버튼, 화면 금액, 남은 시간을 보여주고 `결제 진행`·`취소` 버튼을 붙인다. 버튼은 소유자만 누를 수 있다. 시간이 지나면 메시지를 "결제하지 않았어요"로 바꾼다.

## 확인한 것

- 전체 테스트 694개가 통과했다. 이번 변경으로 추가하거나 바꾼 테스트가 포함되어 있다: 결제와 일반 버튼 구분, 소유자 요청 권한이 없을 때 거부, 시간 초과 시 정리, 다른 사람 버튼 클릭 차단, 채널 버튼으로 승인한 결과가 MCP까지 전달되는지.
- 2026-11-07 15:08(서버 시각)에 배포했다. 배포 파일은 `approvals.py`, `android_control.py`, `gateway.py`, `mcp_server.py` 4개다.
  - `mcp_server.py`는 로컬 파일을 그대로 올리지 않았다. 로컬에는 다른 작업에서 추가한 미배포 플러그인 로더가 들어 있었기 때문이다. 대신 서버 파일에 이번 승인 변경만 적용했다.
  - 적용한 파일로 관련 테스트 107개가 통과하는 것을 확인했다.
- 배포 직후 확인한 것:
  - 서비스가 active이고 Discord Gateway에 연결됐다.
  - 서버의 `.env`가 `DAEVIS_MCP_APPROVAL=discord`이다.
  - 서버에서 정책을 직접 호출해 봤다. 검색 Enter는 자동 허용됐고, 결제는 승인 파일에 `allow`를 쓴 뒤에 허용됐다.
- 실제 Discord에서 결제 버튼이 표시되는지는 확인하지 않았다. 확인하려면 실제 결제 화면이 필요하기 때문이다.

## 아직 모르는 것

- Hermes 설정 파일의 MCP 환경값에는 `deny`가 적혀 있다. 그런데 작업 실행기(`hermes-worker.py`)가 게이트웨이 프로세스의 환경값을 MCP 서버로 넘기고, 배포 전에 실제로 DM 승인 요청이 온 적이 있다. 그래서 `discord` 값이 적용되고 있다고 판단했다. 다만 실제 결제 요청으로 직접 확인하지는 않았다.
- 결제 문구가 없는 결제 버튼이 있는 앱(예: 금액만 적힌 버튼)은 걸러내지 못한다.

## 셀프 인터뷰

1. **왜 결제 말고는 전부 풀었나요?** 요청은 소유자 본인만 보낼 수 있고, 일반 작업마다 확인을 받으면 소유자가 쓰기 불편하다고 판단했기 때문입니다. 되돌릴 수 없고 돈이 나가는 결제만 남겼습니다.
2. **DM을 아예 쓰지 않으면 개인정보는 어떻게 되나요?** 결제 확인 메시지에는 앱 이름, 버튼 문구, 금액만 넣었습니다. 배송지가 보일 수 있는 결제 화면 스크린샷은 붙이지 않았습니다.
3. **MCP 프로세스가 죽으면 버튼은 어떻게 되나요?** 응답 파일을 읽을 프로세스가 없으니 결제는 실행되지 않습니다. 버튼은 시간이 지나면 사라집니다.
