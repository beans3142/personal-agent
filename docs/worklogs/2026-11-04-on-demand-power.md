# 서버를 쓸 때만 켜고, 켜는 일은 다른 서버에 맡겼다

> 2026-11-02 ~ 2026-11-04 · `30e7fc5` · 30일 $60.43 예상을 하루 1시간 사용 기준 $5.96으로 낮추고, Discord 한마디로 켜고 끄게 했다

## 무엇이 문제였나

AWS 크레딧은 정해진 금액이다. AWS 가격 API로 계산하니 두 서버를 30일 내내 켜 두면 $60.43이었다. 쓰는 시간은 하루 한두 시간인데 나머지 시간도 돈이 나갔다.

서버를 끄면 이번엔 다른 문제가 생긴다. Discord 봇이 그 서버 안에 있어서, 꺼진 서버는 "켜"라는 말을 들을 수 없다.

## 고를 수 있던 방법

| 방법 | 판단 |
| --- | --- |
| 계속 켜 두기 | 30일 $60.43이라 버림 |
| 켜는 전용 봇 토큰을 하나 더 만들기 | 토큰 하나로 운영하기로 해서 버림 |
| Lambda 주소를 휴대폰 단축어로 부르기 | 검토했지만 Discord 한마디로 켜는 쪽을 고름 |
| 이미 상시 켜 둔 작은 서버에 전원 봇 올리기 | 고름. 새 AWS 자원을 만들지 않음 |

## 바꾼 것

- **전원 봇** (`agent/power_bot.py`, `agent/power.py`): 이미 상시 운영 중인 다른 작은 서버(t3.micro)에 올렸다. 같은 봇 토큰을 쓰고, 정해진 문장만 정규식으로 받는다. 이름(대비스, 오타 데비스·대비쓰·대빗스·대비즈·ㄷㅂㅅ)과 동작어(온라인·켜 / 오프라인·꺼 / 상태)가 정확히 맞아야 한다. 문장 중간에 섞인 단어로 서버가 꺼지는 일을 막으려는 것이다.
- **권한 최소화**: 봇 토큰과 소유자 ID는 AWS Parameter Store에 SecureString으로 둔다. IAM 정책은 본체 서버 시작·중지와 두 파라미터 읽기만 허용한다.
- **유휴 자동 종료**: 본체는 요청이 120분 없으면 스스로 꺼진다. 요청을 처리하는 중이거나, 자동응답이 켜져 있거나, 예약이 남아 있으면 끄지 않는다(`idle_shutdown_due`, `tests/test_idle_safety.py`).

## 틀린 지점

같은 토큰을 두 프로세스가 쓰니, 본체가 켜져 있을 때 "대비스 상태"에 두 봇이 같이 답할 수 있었다. 본체 게이트웨이가 전원 봇과 같은 판별 함수(`power_command`)로 전원 문장을 무시하게 했다.

## 확인한 것

2026-11-05 새벽에 "대비스 꺼줘"를 보낸 뒤 AWS CLI로 상태를 조회했다. 본체 서버는 `stopped`, 마지막 전환 시각이 요청 시각과 같았다. 꺼질 때는 "끄고 있어요"만 보내고 완료 알림은 보내지 않는다. 켤 때만 6분까지 상태를 확인해 "켜졌어요"를 보낸다.

## 아직 모르는 것

- 전원 IAM 정책은 다른 프로젝트의 CloudFormation 스택 밖에서 붙였다. 그 스택을 갱신하면 사라질 수 있다.
- 서버가 꺼져 있을 때 보낸 일반 요청은 처리되지 않고 사라진다. 켜질 때 놓친 메시지를 다시 읽는 코드가 없다.

## 셀프 인터뷰

**새 서버를 만들지 않고 다른 프로젝트 서버를 빌린 이유는요?**
추가 요금 0원이 조건이었습니다. 이미 24시간 켜져 있는 서버에 81MB짜리 프로세스 하나를 더 올리는 비용은 거의 없습니다. 대신 권한은 시작·중지와 파라미터 읽기로 좁혔습니다.

**유휴 종료가 작업 중에 서버를 끄면 어떡하나요?**
처리 중인 요청, 켜진 자동응답, 남은 예약이 하나라도 있으면 끄지 않습니다. 이 조건은 테스트로 고정해 뒀습니다.

**이 작업에서 배운 점은요?**
비용을 줄이는 결정 하나가 새 문제(꺼진 봇은 못 듣는다)를 만든다는 점입니다. 그래서 결정마다 치른 대가를 같이 적어 두게 됐습니다.
