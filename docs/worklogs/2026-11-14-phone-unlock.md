# 요청받은 폰 작업에서 화면 잠금 비밀번호 입력하기

> 2026-11-14 · 관련 Python 테스트 21개, 잠금 해제 흐름 Java 테스트 6개 통과

## 무엇이 문제였나

폰 앱은 비밀번호 잠금이 있으면 화면 조작을 중단했다. 소유자가 잠금 해제까지 맡기더라도 요청을 처리할 수 없었다.

## 바꾼 것

비밀번호는 서버의 Parameter Store SecureString에 기기별로 보관한다. 등록된 폰이 메인 에이전트에서 받은 실행 중 작업을 제시해야 값을 받을 수 있다. 작업별 한 번만 제공하고, 기기별 5분 간격을 둔다. 비밀번호를 작업 payload나 모델 응답에 넣지 않는다.

폰 앱은 시스템 잠금 화면의 비밀번호 입력칸을 찾은 뒤 값을 받아 한 번 입력한다. 잠금이 풀렸는지 확인하고 원래 작업을 실행한다. 입력 실패 시 잠금 화면 요소를 업로드하지 않는다. 기존의 작업 후 다시 잠그는 동작은 유지한다.

## 확인한 것

등록 기기·작업 소유자·실행 상태·만료·재사용·자격증명 조회 실패에 대한 테스트를 실행했다. 폰 도구와 카톡 루틴 회귀 테스트까지 Python 21개가 통과했다. Java에서는 성공, 이미 열린 화면, 입력칸 부재, 비밀번호 거절, 입력 실패, 조회 오류 6개 사례가 통과했다. 기존 Java 규칙 테스트도 통과했다.

상시 서버에 전달 경로를 배포했고, 서버가 암호화된 설정을 읽을 수 있는지 값을 출력하지 않고 확인했다. 서비스가 active임을 확인했다.

## 아직 모르는 것

실사용 폰의 보안 입력칸이 접근성 입력을 허용하는지는 새 APK 설치 후 확인해야 한다. 단위 테스트는 실기기 잠금 해제 성공의 근거가 아니다. 잠금 해제를 실패하면 자동 반복 입력하지 않는다.

GitHub Actions APK 빌드가 통과했고, 산출물 APK를 다운로드해 소유자 Discord DM에 첨부했다. Discord 응답에서 첨부 파일 한 개를 확인했다. 이 시점의 에뮬레이터 기동 검사는 진행 중이며, 실기기에 설치되었다고 주장하지 않는다.

## 셀프 인터뷰

**왜 서버의 일반 입력 도구로 처리하지 않았습니까?**
기존 앱이 잠긴 화면에서는 명령을 실행하지 않았습니다. 비밀번호가 모델과 작업 기록에 들어가지 않도록 별도 전달 경로를 두었습니다.

**비밀번호를 바꿀 때 앱을 다시 설치해야 합니까?**
아닙니다. 기기별 서버 설정만 바꾸면 됩니다.

**모든 계정 비밀번호 관리 서버입니까?**
아닙니다. 이번 변경은 등록된 폰의 잠금 해제에 한정됩니다.
