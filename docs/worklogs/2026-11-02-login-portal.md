# 서버 IP에서 막힌 로그인을 휴대폰 링크로 풀었다

> 2026-11-02 · `902aa68` `c46e1f8` `59e11aa` · 사람이 한 번 로그인하면 Agent는 저장된 세션을 다시 쓴다

## 무엇이 문제였나

Agent는 AWS 서버에서 돈다. 서버 브라우저로 네이버에 비밀번호 로그인을 시도하자 캡차가 떴고, QR 로그인은 네트워크 오류가 났다. 같은 시기에 coupang.com과 yogiyo.co.kr은 AWS IP를 403으로 막았고, 코레일 비공식 라이브러리는 `MACRO ERROR`로 막혔다. 카카오톡은 기존 휴대폰에서 보조 기기 승인을 해 줘야 했다.

## 왜 그런 일이 생겼나

데이터센터 IP에서 처음 보는 기기가 로그인하면 서비스는 자동화로 의심한다. 코드를 아무리 다듬어도 서버 IP와 새 기기라는 조건은 바뀌지 않는다.

## 고를 수 있던 방법

| 방법 | 판단 |
| --- | --- |
| 캡차를 풀거나 우회 | 계정 보안을 우회하는 방식은 한 번 되더라도 계정 잠금으로 이어질 수 있어 하지 않음 |
| 서버에 가짜 패스키나 가상 인증기 | 같은 이유로 하지 않음 |
| 서버 화면을 휴대폰으로 열어 사람이 로그인 | 고름 |

## 바꾼 것

- `902aa68`: 서버 브라우저 화면을 noVNC로 열고, Cloudflare 임시 터널 링크를 휴대폰으로 보내는 로그인 포털을 만들었다. 사람이 그 화면에서 직접 로그인하면 세션이 서버에 저장되고, Agent는 그 세션을 다시 쓴다. 링크는 필요할 때만 열고 30분이 지나면 닫는다.
- `c46e1f8`: 같은 방식으로 서버 Android 화면도 열었다. 카카오톡 보조 기기 로그인을 여기서 했다.
- `59e11aa`: Android 포털이 느려서 입력을 adb로 보내고 화면 애니메이션을 껐다.
- `8a91668`: 메일이나 Discord 메시지를 보낸 뒤에도 사이트 세션을 다시 저장하게 했다.

## 아직 모르는 것

세션이 만료되면 사람이 다시 들어가야 한다. 이 시점에는 만료를 알려 주는 DM이 없어서 로그에만 남았다.

## 셀프 인터뷰

**자동으로 로그인하면 더 편하지 않나요?**
편하지만 서버 IP에서 보안 확인을 넘기는 순간 계정이 잠길 수 있습니다. 로그인은 한 달에 몇 번이고 Agent 사용은 하루에 수십 번입니다. 드문 일은 사람이 하고 잦은 일은 Agent가 하는 쪽이 계정을 지키는 데 맞다고 봤습니다.

**포털 링크가 외부에 열리는 건 위험하지 않나요?**
그래서 링크는 필요할 때만 만들고 30분 뒤 닫습니다. 열려 있는 시간을 짧게 두는 것이 이 방식의 안전장치입니다.

**이 작업에서 배운 점은요?**
막힌 원인이 코드가 아니라 환경(서버 IP, 새 기기)이면 코드로 이기려 하지 말고 사람의 손을 한 번 빌리는 설계가 낫다는 점입니다.
