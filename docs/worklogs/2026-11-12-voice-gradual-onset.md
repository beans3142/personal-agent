# 조용히 시작한 말소리를 주변 소음으로 학습하던 문제

> 2026-11-12 · 관련 테스트 99개 통과 · 실제 사용자 호출어 인식률은 적용 후 재확인 필요

## 문제와 원인

사용자가 호출어를 세 번 말해도 반응하지 않는다고 보고했다. 실행 중인 앱, 듣기 설정, 기본 입력 장치를 확인했다. 입력은 USB 마이크이며 음소거가 아니고 Windows 입력 볼륨은 100%였다. GPU 인식 DLL도 프로세스에 로드되어 있었다. 따라서 음소거나 프로세스 종료로 단정할 근거는 없었다.

기존 Segmenter는 활성 문장이 아닌 모든 프레임을 배경 소음 추정에 반영했다. 합성 입력으로 조용한 배경 뒤에 0.9초 동안 서서히 커지는 작은 말소리를 넣었더니 문장 구간이 하나도 나오지 않았다. 말소리 자체가 문턱을 올려 버리는 문제가 재현됐다. 이것이 실제 사용자 발화 실패의 유일한 원인인지는 확인되지 않았다.

## 변경

배경 추정치를 갱신하는 입력을 기존 배경 수준의 1.5배 이하로 제한했다. 커지는 말소리가 자신의 검출 문턱을 계속 올리지 않게 한다. 기존 절대 문턱과 호출어 패턴은 유지했다.

PC 에이전트에 문장 길이, 입력 최대값, 인식 시간, 호출어 감지 여부를 기록한다. 원음과 인식된 문장은 이 진단 기록에 넣지 않는다. 무반응과 인식 실패를 구분할 근거가 없었던 문제를 줄이기 위한 것이다.

## 검증

새 회귀 테스트는 수정 전 0개 문장으로 실패했고, 수정 후 1개 문장을 검출했다. 일정한 낮은 배경음이 문장을 시작하지 않는 경우도 확인했다. 음성·데스크톱 관련 테스트 99개가 통과했다.

실제 마이크 8초와 25초 측정에서 낮은 입력을 관찰했지만, 해당 구간에 사용자의 시험 발화가 포함됐는지는 확인하지 못했다. 사용자는 그 뒤 세 번 호출했다고 알려 왔다. 이를 수집된 시험 발화라고 간주하지 않는다.

## 한계와 후속 확인

실제 발화의 호출어 감지는 새 앱을 설치한 뒤 사용자 발화와 진단 기록을 대조해야 한다. 합성 신호 테스트 통과를 실제 인식률 향상으로 주장하지 않는다. 주변 소음이 점차 커지는 환경에서는 문장 검출이 늘 수 있다. 인식기에서 호출어가 확인되어야 요청이 전달되는 기존 조건을 유지한다.

## 셀프 인터뷰

**입력 볼륨을 올리면 충분하지 않나요?**
이미 Windows 볼륨이 100%였습니다. 배경 추정 코드의 문제는 별도로 재현됐습니다.

**인식 모델을 바꿨나요?**
아닙니다. 이번 변경은 모델에 전달할 문장을 자르는 단계에 한정했습니다.

**실제 개선은 어떻게 판단하나요?**
사용자가 말한 시점에 문장 검출과 호출어 인식 기록이 남는지 먼저 확인해야 합니다.
