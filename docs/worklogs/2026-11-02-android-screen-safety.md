# 모델이 엉뚱한 버튼을 누르고, 입력창을 못 본 이유

> 2026-11-02 · `2bcd0ea` `ea8e49b` `f2f94ca` `b010cfa` · 클릭에 "기대하는 글자"를 같이 받고 화면 결과를 자르지 않도록 바꿨다

## 무엇이 문제였나

두 가지 사고가 있었다.

첫째, 모델이 카카오톡 대신 런처 앱을 눌렀다. 화면 노드 번호를 넘겨야 하는데 목록 순번을 넘겼다. 회전 배너 때문에 노드 번호가 밀리는 일도 있었다.

둘째, 태블릿에서 카카오톡 채팅방을 열었는데 모델이 입력창을 찾지 못했다. 스크린샷에는 오른쪽에 입력창이 분명히 있었다.

## 왜 그런 일이 생겼나

첫째 사고는 클릭 도구가 번호 하나만 믿었기 때문이다. 번호가 틀려도 그 번호에 무언가 있으면 그대로 눌렀다.

둘째 사고는 도구 결과 길이 제한 때문이었다. 태블릿 화면 구조는 약 16,000자인데 모든 도구에 공통으로 걸린 결과 제한이 8,000자였다. 왼쪽 채팅 목록까지만 모델에게 가고 오른쪽 입력창은 잘려 나갔다.

## 고를 수 있던 방법

| 방법 | 판단 |
| --- | --- |
| 프롬프트에 "번호를 잘 확인하라"고 적기 | 확률적으로 다시 틀려서 버림 |
| 클릭 때 노드 ID와 기대하는 버튼 글자를 같이 받기 | 고름. 둘이 안 맞으면 누르기 전에 실패 |
| 결과 제한을 전체적으로 늘리기 | 화면이 쌓일수록 입력 토큰이 커져 버림 |
| 화면 결과만 자르지 않고, 지난 화면은 "교체됨"으로 바꾸기 | 고름 |

## 바꾼 것

- `2bcd0ea`, `f2f94ca`: `android_click`이 노드 ID와 기대 글자를 함께 받는다. 화면이 바뀌어 글자가 안 맞으면 누르지 않고 실패한다. 행동 전에는 반드시 새로 관찰한 화면이 있어야 하고 마지막 입력 직전에 같은 노드를 다시 찾는다.
- `b010cfa`: Android 화면 결과는 8,000자 제한에서 뺐다. 대신 새 화면을 받으면 지난 화면 결과를 "교체됨" 표시로 바꿔서 입력이 계속 쌓이지 않게 했다.
- `ea8e49b`: 이때부터 모든 답장 끝에 처리 시간, 입력·출력 토큰, 모델·도구 호출 수를 붙였다. 무엇이 비싼지 감이 아니라 숫자로 보기 위해서다.

## 확인한 것

`2bcd0ea`와 `f2f94ca`에서 `tests/test_android_control.py`에 클릭 대상 확인 테스트를, `b010cfa`에서 `tests/test_loop.py`에 긴 화면 결과가 잘리지 않는 테스트를 추가했다. 이후 카카오톡 전송은 태블릿 화면의 입력창을 찾아 진행됐다.

## 셀프 인터뷰

**클릭 실패가 늘면 사용성이 떨어지지 않나요?**
늘어납니다. 그래도 잘못 누르는 것보다 낫다고 봤습니다. 메시지 전송이나 결제는 되돌릴 수 없습니다. 실패하면 모델이 화면을 다시 보고 다시 고르면 됩니다.

**제한을 그냥 16,000자로 올리면 되지 않았나요?**
그러면 모든 도구 결과가 커지고 화면을 여러 번 보면 그만큼 입력이 쌓입니다. 꼭 필요한 화면만 자르지 않고 다 쓴 화면은 치우는 쪽이 토큰과 정확도를 둘 다 지킵니다.

**이 작업에서 배운 점은요?**
모델이 틀렸을 때 모델 탓을 하기 전에 모델이 실제로 받은 입력을 봐야 한다는 점입니다. 입력창 사고는 모델 문제가 아니라 8,000자에서 잘린 입력 문제였습니다.
