# 대비스가 소유자 폰을 직접 조작하기

> 2026-11-14 · 커밋은 산출물 참고 · Galaxy 앱의 접근성 서비스로 화면 읽기·누르기·입력, 카톡 1:1 전송 루틴. 서버 Android에서 전송 직전까지 확인, 실기기는 잠금 때문에 미완료

## 무엇이 문제였나

카톡·배민 같은 앱 조작은 서버 안의 안드로이드(ReDroid)에서만 됐다. 소유자는 자기 폰을 직접 다루게 해서, 장기적으로 서버 에뮬레이터를 줄이고 싶어 했다. 성공 기준은 "내 폰 카톡으로 반수의신에게 시험 메시지가 실제로 가는 것"이었다.

## 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| 모델이 화면을 보고 한 단계씩 조작 | 앱마다 코드가 필요 없다 | 서버 Android 시험에서 31단계·입력 10만 토큰을 쓰고도 나와의 채팅을 못 열어, 카톡 전송에는 버림 |
| 카톡 전송을 정해진 루틴으로 | 모델 호출 없이 빠르고 매번 같다 | 고름 (`phone_kakao_send`). 일반 조작 도구는 다른 앱용으로 남김 |
| 화면 이미지(스크린샷) 전송 | 모델이 그림을 본다 | 접근성 트리로 충분하고 데이터가 작아 넣지 않음 |

## 바꾼 것

- 앱(`DaevisAccess`, `PhoneTask`): 접근성 서비스가 화면 요소 목록(글자·설명·위치·누를 수 있는지), 누르기, 입력, 뒤로·홈·엔터, 앱 열기, 스크롤을 한다. 요청이 없을 때는 아무 이벤트도 처리하지 않는다. 결과 화면은 중계 서버에 파일로 올리고 1시간 뒤 지워진다.
- 중계 서버: `phone_task` 작업과 폰 등록 시 메인 에이전트 권한을 추가했다. 롱폴링 대기 확인 간격을 0.3초로 줄였다.
- 메인 에이전트: `phone_screen/tap/type/key/open/scroll`. 결제 버튼은 서버 Android 도구와 같은 승인 절차를 탄다.
- `agent/phone_kakao.py` `phone_kakao_send`:
  - 카톡 열기 → 검색 → 정확한 이름의 1:1 방 → 제목 확인 → 입력칸 누르기 → 입력 → 전송 → 새 말풍선 확인 순서로 진행한다.
  - 결과가 애매하면 `KAKAO_UNCERTAIN`으로 답하고 다시 보내지 않는다.
  - 폰이 잠겨 있으면 바로 멈춘다.
  - 게이트웨이의 서버 카톡 빠른 경로는 "폰으로" 요청을 건너뛴다.
- 앱(`WakeActivity`): 작업 전에 화면을 켜고, PIN이 필요 없는 잠금(Smart Lock)일 때만 잠금을 넘긴다. 대비스가 켰으면 마지막 작업 20초 뒤 다시 잠근다. PIN 잠금이면 아무것도 하지 않는다.

## 확인한 것

- 관련 테스트(전체 테스트는 돌리지 않음): `test_phone_tools` 7개, `test_phone_kakao` 6개, `test_gateway` 36개, `test_mcp_server` 27개, `test_progress` 11개 통과.
- CI APK 빌드와 에뮬레이터 실행 확인 통과. 한 번은 에뮬레이터의 구글 서비스가 죽어 실패했고, 다시 돌려 통과했다.
- 서버 Android에서 확인했다.
  - 접근성 연결 뒤 화면 읽기에 0.5초 걸렸다.
  - `phone_kakao_send` dry-run은 8.6초 걸렸다. 반수의신 1:1 방을 열고 제목을 확인했으며, 보내지는 않았다.
  - 입력칸을 누른 뒤 글자를 넣어야 Send 버튼(`send_button_layout`)이 나타나는 것을 확인했다. 입력한 글자는 지웠다.
- 소유자 폰에서 실제 요청 1회: 9단계가 모두 1초 안팎에 응답했다. 다만 화면이 잠금 화면(systemui)이라 카톡이 열리지 않아 `KAKAO_NOT_SENT`로 끝났다. 전송된 것은 없다.

## 틀린 지점

- 처음 카톡 시험을 모델의 단계 선택에 맡겼다. 정해진 흐름이 있는 일은 코드 루틴이 맞았다.
- 방 제목은 text가 아니라 description에 있었고, 검색창 옆의 숨은 입력칸(`input_focus`)도 있었다. 화면을 직접 보기 전에 서버 Android 루틴의 가정을 그대로 썼다.

## 아직 모르는 것

- 실제 전송 버튼을 누르고 말풍선을 확인하는 마지막 단계는 아직 한 번도 돌지 않았다.
- 화면 켜기·잠금 넘기기·다시 잠그기는 빌드만 통과했다. 실기기 Smart Lock 상태에서는 시험하지 않았다.
- 폰 앱에서 "내 PC 꺼줘"(반대 방향)는 아직 시험하지 않았다.
- 소유자가 폰을 쓰는 중에는 대비스 조작과 충돌한다. 막는 장치는 아직 없다.

## 셀프 인터뷰

**PIN을 대신 입력하면 되지 않나요?**
접근성으로 PIN 버튼을 누르는 것은 기술적으로 가능합니다. 하지만 비밀번호를 서버나 앱에 보관해야 해서 만들지 않았습니다. PIN 없이 풀리는 Smart Lock 조건에서만 엽니다.

**서버 에뮬레이터를 없앨 수 있나요?**
아직은 아닙니다. 폰은 잠겨 있거나 사용 중일 때가 많고, 그때는 조작할 수 없습니다. 당분간은 둘을 함께 씁니다.

**화면 내용이 모델에게 가나요?**
일반 조작 도구는 화면 글자를 모델에게 보냅니다. 카톡 루틴은 코드가 판단하고 결과 코드만 넘깁니다.
