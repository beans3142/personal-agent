# 채용 페이지에 읽음 표시, 정렬, 내 경험 근거를 붙이고 출처를 늘렸다

> 2026-11-15 · 읽은 공고는 NEW를 눌러 읽음으로 바꾸면 목록 맨 아래로 내려간다. 정렬 5가지를 고를 수 있고, 카드마다 경력 조건·전형·내 경험과 닿는 요구가 보인다

## 무엇이 문제였나

채용 페이지는 점수 순 목록 하나였다. 이미 본 공고와 처음 보는 공고가 섞여 있어 매일 같은 카드를 다시 훑어야 했다. 정렬을 바꿀 수 없었다. 카드에는 기술 이름이 겹치는지만 나왔다. 경력 조건, 면접 방식, 내 경험 중 무엇이 그 공고에 닿는지는 원문을 열어야 알 수 있었다.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| 읽음 기록을 서버에 저장 | PC와 휴대폰이 같은 기록을 본다 | 정적 페이지에 쓰기 API와 로그인을 새로 붙여야 해서 이번에는 버림 |
| 읽음 기록을 브라우저 저장소에 둔다 | 서버 변경 없이 바로 동작 | 고름. 기기마다 기록이 따로라는 제약은 페이지에 적었다 |
| 모든 공고를 모델로 요약 | 정보가 가장 많다 | 공고 300여 건을 매일 요약하면 토큰이 크다. 버림 |
| 내 경험 근거는 코드로, 요약은 상위 공고만 모델로 | 근거는 토큰 0, 요약은 본문 해시로 캐시해 새 공고만 호출 | 고름 |

## 바꾼 것

- 카드마다 NEW 버튼을 둔다. 누르면 "읽음 ✓"로 바뀌고 흐리게 표시되며 그 목록의 맨 아래로 내려간다. 다시 누르면 NEW로 돌아온다. "안 읽음" 필터 탭을 추가했다.
- 정렬: 점수 높은 순, 마감 임박 순, 최근 발견 순, 회사 평점 순, 직무 적합 순. 고른 정렬은 다음 방문에도 유지된다.
- 카드에 경력 조건과 전형 단계를 항상 보인다.
- 포트폴리오 대조 결과를 카드에 붙였다. 공고가 요구한 기술마다 내가 어디서 썼는지 한 줄씩 보이고, 경력·졸업·언어·연봉 관문 판정이 칩으로 보인다. 자세히를 펼치면 지원 방향과 앞세울 경험이 나온다.
- 링크를 아는 사람은 누구나 페이지를 열 수 있다. 그래서 회사 내부 수치가 담긴 경험은 본문 없이 "어디서 썼는지"만 보인다.
- 모델 요약 대상을 상위 10건에서 40건으로 늘렸다. 요약 항목에 경력·학력 조건과 면접·과제 세부(코딩테스트 언어, 면접 횟수와 형식)를 더했다.
- 공고 요약 모델을 ChatGPT 우선, Claude 다음으로 바꿨다. 이날 Claude CLI가 "조직에서 Claude Code 구독 접근을 껐다"는 오류로 모든 요청을 거절해 요약이 0건이 됐기 때문이다. 한 묶음 크기를 7,000자로 줄여 ChatGPT 화면 응답 시간(85초) 안에 끝나게 했다.

### 출처 확장

- 기업 공식 채용 사이트 11곳을 더했다. 그리팅으로 운영하는 카카오페이·카카오모빌리티·현대오토에버·무신사·컬리·직방·와디즈·마이리얼트립·스푼라디오는 페이지에 실린 공고 목록의 경력 구분(신입·경력 무관)과 공고 본문을 읽는다. 우아한형제들은 공식 채용 API의 최소 경력 0년 공고만, LINE은 국내 근무지이면서 제목에 신입이 있는 공고만 받는다.
- 사람인 신입 검색어를 3개에서 8개(자바 개발, 웹 개발, DevOps, 데이터 엔지니어, 클라우드 엔지니어 추가)로, 검색어마다 최대 2쪽(200건)으로 넓혔다.
- 접속 확인만 하고 공고는 읽지 않던 잡코리아·캐치·인큐커리어 줄을 뺐다. 캐치는 robots.txt가 해당 경로를 막고, 잡코리아는 AI 수집기를 막는다. 로켓펀치와 쿠팡 채용 페이지는 봇 확인 화면을 띄워 넣지 않았다.

## 확인한 것

- 관련 테스트 4개를 먼저 추가했고, 브리핑 비공개 테스트 70개가 통과했다.
- 실제 배포 페이지(내장 브라우저)에서: NEW를 누르니 카드가 0번째에서 314번째(맨 아래)로 이동했고 버튼이 "읽음 ✓"로, 안 읽음 탭이 315→314로 바뀌었다. 새로고침 뒤에도 읽음과 정렬 선택이 유지됐다. 마감 임박 순으로 바꾸면 오늘 마감 공고가 위로 왔다. 375px 폭에서 가로 넘침 없음, 콘솔 오류 없음.
- 배포 페이지에서 회사 내부 수치 문자열을 검색해 0건을 확인했다.
- 공고 324건 중 307건에 내 경험 근거가 붙었고, 요약 40건 모두 경력·면접 항목이 채워졌다(1회 실행).
- 출처 확장 뒤 전체 수집 1회: 표시 공고가 324건에서 561건으로 늘었고, 이날 처음 찾은 공고가 231건이었다. 사람인 검색어 8개가 200건 상한에 걸린 것은 6개였다.
- 새 공식 출처 11곳만 따로 돌린 1회 실행에서 신입·경력 무관 개발 공고 4건(카카오페이 2, 카카오모빌리티 2)이 새로 잡혔다. 나머지 9곳은 이날 해당 공고가 없었다.

## 아직 모르는 것

- 읽음 기록은 브라우저마다 따로 저장된다. PC에서 읽음으로 바꾼 공고가 휴대폰에서는 NEW로 보인다.
- 기술 동향 보고서의 상세 분석은 Claude 접근 차단으로 이날 생성되지 않았다(원문 발췌로 표시).
- 공식 사이트는 경력직 공고가 대부분이라 새 공식 출처의 기여는 작다(1회 실행 4건).
- 사람인 확장분은 목록 정보(경력·마감·근무지)만 있고 본문이 없어, 요약과 내 경험 근거가 얕다. 섞여 들어온 리드·경력직 제목은 거르게 했지만 그 필터는 다음 실행부터 적용된다.

## 셀프 인터뷰

**왜 읽음 기록을 서버에 두지 않았나요?**
페이지는 정적 파일로만 배포됩니다. 서버에 저장하려면 쓰기 API와 본인 확인을 붙여야 합니다. 먼저 한 기기에서 쓰는 흐름을 확인하고, 기기 간 공유가 필요하면 그때 붙입니다.

**내 경험 근거는 모델이 쓰나요?**
아닙니다. 포트폴리오의 기술별 사실 목록과 공고 문장을 코드로 대조합니다. 모델은 상위 40건의 요약에만 쓰고, 같은 공고 본문은 캐시해 다시 호출하지 않습니다.

**공개 링크인데 포트폴리오 내용이 노출되지 않나요?**
공개로 표시한 사실만 본문을 보여 줍니다. 회사 내부 수치가 담긴 사실은 경험한 곳의 이름만 보입니다. 이 규칙은 테스트로 묶었습니다.
