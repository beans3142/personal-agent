# PC 세션 중계기를 서버의 Agent 루프로 바꿨다

> 2026-11-02 · `b1745e2` `2524a56` · PC를 꺼도 도는 Agent가 됐고, 첫 시험에서 나온 예약 오작동은 도구를 둘로 나눠 고쳤다

## 무엇이 문제였나

처음 만든 것은 PC에서 돌고 있는 Claude Code 세션에 Discord 메시지를 넘기는 통로였다. 이름은 Agent였지만 실제로는 중계기였다. PC를 끄면 멈췄고, Agent가 직접 가진 도구도 기억도 없었다. "서버에서 24시간 돌고, Discord 한마디로 일을 끝낸다"는 목표와 맞지 않았다.

## 고를 수 있던 방법

| 방법 | 장점 | 판단 |
| --- | --- | --- |
| PC 세션 중계를 계속 쓰기 | 이미 동작함 | PC가 켜져 있어야 해서 버림 |
| 게이트웨이, 루프, 도구를 직접 작성 | 도구와 승인 규칙을 코드로 통제 | 고름 |

## 바꾼 것

`b1745e2`에서 서버에서 혼자 도는 구조를 새로 짰다. 바뀐 파일은 25개, 추가 1,315줄이다.

- `agent/gateway.py`: Discord 연결, 소유자 확인, 승인 버튼, 예약 실행
- `agent/loop.py`: 모델 호출과 도구 실행을 반복하는 루프, 단계 한도
- `agent/codex.py`: ChatGPT 구독 로그인(Codex OAuth)으로 모델 호출, 토큰 갱신
- `agent/memory.py`, `agent/scheduler.py`: SQLite 기억과 대화 기록, 알림 예약

모델은 API 키 대신 이미 쓰고 있는 ChatGPT 구독으로 부른다. 추가 요금이 나가지 않게 하려는 것이다.

## 틀린 지점

첫 시험에서 1회 알림을 요청했는데 모델이 1분마다 반복되는 예약을 등록했다. 예약 도구 하나에 1회 알림과 반복 알림 두 가지 뜻이 함께 들어 있었고, 모델이 그중 틀린 쪽을 골랐다. 프롬프트를 고치는 대신 `2524a56`에서 도구를 `schedule_add`(1회)와 `schedule_repeat`(반복)로 나눴다. 도구 이름만 보고도 고를 수 있으면 모델이 헷갈릴 여지가 줄어든다.

## 아직 모르는 것

이때는 모든 요청이 모델을 2~4번 불렀다. 그 호출이 어디에 쓰이는지는 이후 토큰 측정에서 따로 쟀다.

## 셀프 인터뷰

**처음부터 Agent 프레임워크를 쓰지 않은 이유는요?**
그때는 OpenClaw나 Hermes가 구독 로그인을 지원하지 않는다고 잘못 알고 있었습니다. API 요금이 든다고 보고 직접 짰습니다. 이 판단은 이틀 뒤 틀린 것으로 확인했고, 그때 본체를 Hermes로 옮겼습니다. 직접 짠 도구는 그대로 살렸습니다.

**예약 버그를 프롬프트로 고치지 않은 이유는요?**
프롬프트는 확률적으로 샙니다. 도구 하나에 두 가지 뜻이 있으면 모델은 언젠가 다시 헷갈립니다. 도구를 나누면 구조가 실수를 막아 줍니다.

**이 단계에서 배운 점은요?**
"Agent"라는 이름보다 어디서 돌고, 무엇을 통제하는지가 중요하다는 점입니다. 중계기는 편했지만 서버, 도구, 승인 중 어느 것도 제 손에 없었습니다.
