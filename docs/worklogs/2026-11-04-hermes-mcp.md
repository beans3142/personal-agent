# 본체는 Hermes로 옮기고, 한국 서비스 도구는 MCP 서버로 떼어 냈다

> 2026-11-04 · `aa4b129` `30e7fc5` · 직접 만든 도구를 버리지 않고 본체만 바꿨다. 연결 시험 한 번은 9.7초, 입력 7,077 토큰

## 무엇이 문제였나

직접 짠 Agent로 카톡, 지도, 메일까지는 됐다. 그런데 하트비트, 기기 노드, 기억 계층, 컨텍스트 압축처럼 기존 Agent 프레임워크에 이미 있는 기능을 하나씩 다시 만들고 있었다. 반대로 서버 Android 카톡, 네이버 로그인, 네이버 지도 경로는 어느 프레임워크에도 없다.

## 왜 그런 일이 생겼나

처음에 프레임워크를 거른 이유는 "API 요금이 든다"였다. 다시 확인해 보니 Hermes와 OpenClaw 모두 ChatGPT 구독 로그인을 공식 경로로 지원했다. 처음 판단이 틀렸다.

## 고를 수 있던 방법

| 방법 | 판단 |
| --- | --- |
| 직접 만든 본체를 계속 키우기 | 이미 있는 기능을 다시 만드는 비용이 커서 버림 |
| OpenClaw | 스킬과 기기 노드가 강하지만 TypeScript이고, 외부 MCP 서버를 그대로 붙이는지 문서에서 확인하지 못함. 설정 오류로 약 50번 재설치했다는 사용기도 있어 버림 |
| Hermes + 우리 도구를 MCP 서버로 | 고름. Python이라 기존 코드와 언어가 같고, MCP 클라이언트를 설치 후 실제 연결로 확인 |

## 바꾼 것

- `aa4b129`: 우리 도구를 stdio MCP 서버(`agent/mcp_server.py`) 하나로 감쌌다. 기존 게이트웨이와 Hermes가 같은 도구 코드를 쓴다. 본체를 다시 바꿔도 도구는 버리지 않는다.
- `30e7fc5`: Hermes를 요청마다 격리된 작업자 프로세스로 띄우는 `agent/hermes_runner.py`와, Discord 소유자 확인을 그대로 쓰는 `agent/hermes_gateway.py`를 붙였다.
- **도구는 읽기부터 연다**: MCP stdio는 같은 서버 안의 클라이언트를 믿는 구조라 호출한 쪽을 따로 인증하지 않는다. 그래서 허용 목록에 있는 도구만 보이게 했고, 처음에는 `memory_search`, `route_search`, `map_search`, `android_screen` 네 개만 열었다. 쓰기 도구는 기본 거부다.
- **반복 제한**: 입력 토큰 6만, 같은 오류 3회, 소유자 거절 중 하나라도 걸리면 멈춘다(`deploy/hermes_policy.py`).
- Hermes 기본 도구 묶음은 모두 껐다. 일부 기능은 구독과 별도로 OpenRouter 요금이 들기 때문이다.

## 틀린 지점

처음 지정한 모델 `gpt-5.3-codex`는 이 계정에서 HTTP 400으로 거부됐다. 계정의 모델 목록을 조회해 `gpt-5.6-luna`로 바꿨다.

## 확인한 것

MCP `memory_search`를 한 번 거친 시험이 9.7초, 입력 7,077 / 출력 193 토큰이었다. 비교 실험이 아니라 연결 확인 한 건이다.

## 아직 모르는 것

Hermes와 기존 게이트웨이를 같은 작업으로 비교한 실험이 없다. 지금 "Hermes가 낫다"는 근거는 기능 범위뿐이다.

## 셀프 인터뷰

**직접 만든 본체를 버리는 게 아깝지 않았나요?**
버린 건 대화 루프와 그 주변뿐입니다. 시간이 많이 든 부분은 카톡, 로그인, 지도 같은 도구였고, 그건 MCP 서버로 감싸서 그대로 씁니다. 경계를 본체와 도구로 나눈 덕분에 바꾸는 비용이 작았습니다.

**MCP로 감싸면 보안은 괜찮나요?**
stdio라 외부 포트는 열지 않습니다. 대신 같은 서버의 클라이언트를 믿기 때문에, 서버 쪽에서 허용 목록, 공개 채널 숨김, 승인 판단을 직접 합니다. 클라이언트를 믿지 않고 도구 쪽에서 막는 구조입니다.

**이 작업에서 배운 점은요?**
초기 판단의 근거를 적어 두는 게 중요하다는 점입니다. "요금이 든다"는 근거가 틀렸다는 걸 알았을 때, 그 근거에 기대 내린 결정만 골라 다시 열 수 있었습니다.
