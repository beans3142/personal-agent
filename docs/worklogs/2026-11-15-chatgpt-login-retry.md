# ChatGPT 로그인이 만료되면 같은 모델로 한 번 더 시도한다

> 2026-11-15 · 로그인 토큰이 만료된 직후 첫 도구 요청이 "모델 로그인 인증 실패"로 끝나던 문제. 도구가 실행되기 전이면 ChatGPT로 한 번 더 시도한다

## 무엇이 문제였나

도구 작업(Hermes) 시험 요청이 12초 만에 "모델 로그인 인증에 실패했어요"로 끝났다. 바로 다음 요청은 정상으로 처리됐다.

## 원인

- ChatGPT 로그인 토큰은 약 10일마다 만료된다. 만료된 토큰으로 첫 호출이 실패하면 Hermes는 그 직후 토큰을 갱신해 저장한다. 서버의 인증 파일 수정 시각이 실패 직후였고, 갱신된 토큰의 만료일은 11/25였다.
- 실패한 그 요청은 다시 시도하지 않아 그대로 실패로 끝났다.
- 원래 이때 Claude로 넘기게 돼 있었지만, 이날 Claude 쪽이 "조직에서 Claude Code 구독 접근을 껐다"며 모든 요청을 거절해 넘길 곳이 없었다.

## 바꾼 것

- 인증 실패로 끝났고 도구 실행과 카톡 화면 조작이 하나도 없으면, 같은 ChatGPT로 한 번 더 실행한다. 아무것도 실행되지 않았으니 중복 전송은 생기지 않는다.
- 그래도 실패하면 기존대로 Claude 대체를 시도하고, 그것도 실패하면 두 실패를 함께 알린다.

## 확인한 것

- 관련 테스트(Hermes 실행기·정책·워커) 57개 통과. 재시도 성공, 도구 실행 뒤 재시도 안 함, 재시도도 실패하면 Claude로 넘김을 테스트했다.
- 서버에서 갱신된 토큰으로 도구 요청을 2회 실행했다. 둘 다 성공했고 각각 11.1초, 11.7초가 걸렸다.
- 만료 직후 재시도로 성공하는 경로 자체는 다음 만료(11/25 전후) 때 실제로 확인해야 한다.

## 셀프 인터뷰

**왜 바로 Claude로 넘기지 않고 같은 모델로 다시 시도하나요?**
만료는 첫 실패 직후 자동 갱신으로 풀립니다. 같은 모델로 한 번 더 시도하는 쪽이 빠르고, 다른 계정 상태에 기대지 않습니다.

**재시도로 같은 작업이 두 번 실행될 위험은요?**
도구가 하나라도 실행됐거나 카톡 화면을 건드렸으면 재시도하지 않습니다. 인증 실패는 보통 첫 모델 호출에서 나서 그 전에 실행된 것이 없습니다.

**이 작업에서 배운 점은요?**
대체 경로가 하나뿐이면 그 경로가 막힌 날 전체가 멈춥니다. 원인이 일시적인 실패는 같은 경로 재시도로 먼저 흡수해야 합니다.
