# 명확한 PC 종료 요청은 바로 처리하고 이름이 불명확할 때만 확인한다

> 2026-11-07 · 커밋 전 · 관련 테스트 60개 통과 후 멘션 회귀 검사를 추가해 Discord 검사 5개 통과

## 무엇이 문제였나

켜진 Windows PC가 연결되지 않은 것으로 표시됐다. 소유격이 붙은 이름과 데스크톱의 다른 표기도 기존 이름 조회에서 실패했다.

## 왜 그런 일이 생겼나

로컬 PC 수신 프로세스가 없었으며 로그인 자동 실행 항목도 없었다. 수신 프로그램을 다시 실행한 뒤 인증된 서버 조회에서 연결 상태가 참으로 바뀌었다. 자동 실행 항목이 없어진 원인은 확인하지 못했다.

이름 조회는 등록 이름의 정확한 일치만 우선 처리했고, 소유격과 표기 차이를 처리하지 못했다. 새 회귀 검사 3개가 수정 전에 실패하는 것을 확인했다.

## 고른 방법과 바꾼 것

모든 요청을 다시 확인하면 사용자의 조작이 늘어난다. 대상과 종료 의도가 명확하면 기존 60초 종료 요청을 바로 보낸다. 정확한 등록 이름을 우선하고, 그다음 소유격과 데스크톱 표기를 해석한다. 없는 이름을 기본 PC로 자동 대체하지 않는다.

직접 명령에서 이름을 찾지 못했고 연결된 등록 PC가 한 대뿐이면 그 PC를 제안하는 예·아니오 버튼을 보낸다. 모델 경유 종료에서도 명시 대상이 확인되지 않으면 소유자 DM 확인을 요청한다. 확인 버튼은 소유자만 사용할 수 있고, 한 번만 처리하며 등록 식별자와 연결 상태를 다시 확인한다. 명시 대상인 경우 모델 경유 요청도 바로 기존 종료 경로를 사용한다.

연결 실패 응답은 PC 전원 자체가 꺼졌다는 뜻으로 단정하지 않도록 바꿨다. 로컬 수신 프로그램과 로그인 자동 실행 항목을 복구했다.

## 확인한 것

PC·Discord·소유자 제어·깨우기 관련 60개 검사가 통과했다. 이후 명확한 멘션 요청이 확인 질문 없이 종료 처리기로 전달되는 회귀 검사를 추가했고 Discord 검사 5개가 통과했다. 실행기는 검사에서 대역으로 바꿨다. 실제 PC 종료 요청은 시험하지 않았다.

## 아직 모르는 것

실제 종료와 다음 Windows 로그인 후 자동 연결은 사용자 환경에서 확인해야 한다. 일반 기능 전체의 자연어 흐름이나 음성 인식 통합까지 검증한 변경은 아니다. 음성 입력의 인식 오류를 등록 이름만으로 모두 해결할 수 있다고 주장하지 않는다.

## 셀프 인터뷰

**왜 항상 확인하지 않나요?**
대상과 동작이 명확한 요청의 추가 조작을 줄이기 위해서입니다.

**연결 상태가 전원 상태와 같은가요?**
아닙니다. 수신 프로그램의 최근 응답 유무만 확인합니다.

**잘못된 PC에 명령이 전달되는 것을 어떻게 막나요?**
정확한 등록 이름을 우선하고, 확인 버튼을 누를 때 등록 식별자와 연결 상태를 다시 검사합니다.
