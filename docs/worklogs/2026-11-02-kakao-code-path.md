# "이 문장 보내 줘"에 모델 7번은 과했다

> 2026-11-02 · `a0d3cda` · 따옴표로 정한 카톡 메시지를 코드가 직접 보내 20초·모델 7회에서 2.5초·모델 0회로 줄였다

## 무엇이 문제였나

카카오톡 메시지 하나를 보내는 요청을 모델에 맡기자 20초가 걸렸고, 모델을 7번 불렀고, 입력이 50.0k 토큰이었다. 채팅방 찾기, 화면 보기, 입력창 누르기, 입력, 전송, 확인을 단계마다 모델이 판단했기 때문이다. 보낼 문장은 이미 정해져 있는데 모델이 할 일은 사실상 없었다.

## 고를 수 있던 방법

| 방법 | 판단 |
| --- | --- |
| 모델 호출 한도를 늘리고 그대로 두기 | 느리고 토큰이 그대로라 버림 |
| 문장이 정해진 요청은 코드가 처리 | 고름 |
| 모든 카톡 요청을 코드로 처리 | "반갑다고 보내"처럼 문장을 지어야 하는 요청은 모델이 필요해서 버림 |

## 바꾼 것

- 따옴표로 정확한 문장을 준 개인 메시지는 코드가 받는 사람을 확인하고, 입력하고, 전송을 한 번 누르고, 새 말풍선이 생겼는지 확인한다. 성공 기준은 "보냈다"가 아니라 "새 말풍선이 생겼다"다.
- 결과가 애매하면 다시 보내지 않는다. 같은 말이 두 번 가는 것보다 "확인하지 못했습니다"라고 답하는 쪽이 낫다.
- 단체방 자동응답을 추가했다. 모델 없이 5초마다 화면을 읽고, 새 메시지가 있을 때만 도구 없는 제한된 호출을 한 번 한다.

## 확인한 것

| 경로 | 시간 | 모델 호출 | 입력 토큰 |
| --- | --- | --- | --- |
| 모델이 방 찾기부터 처리 | 20초 | 7회 | 50.0k |
| 코드 경로, 이미 열린 방 기준 | 2.5초 | 0회 | 0 |

각각 한 번씩 잰 값이다. 자동응답 호출 한 번은 입력 531, 출력 116 토큰이었다.

## 틀린 지점

자동응답이 답을 보내는 도중에 배포하느라 서비스를 재시작했다. 감시기는 다시 보내지 않고 멈췄다. 화면에서 새로 나간 말풍선이 없는지, 입력창에 남은 초안이 없는지 확인한 뒤에야 이어서 처리했다. 규칙대로 동작했지만 배포 순서가 잘못됐다. 이후 배포는 감시기를 먼저 비우고 보류 상태가 없는 것을 확인한 다음 재시작한다.

## 셀프 인터뷰

**모델을 안 쓰면 AI Agent라고 할 수 있나요?**
Agent의 목적은 일을 끝내는 것이지 모델을 많이 부르는 게 아닙니다. 판단이 필요 없는 단계까지 모델에 맡기면 느리고 비싸고, 단계가 많을수록 틀릴 곳도 늘어납니다. 모델은 문장을 지어야 할 때만 씁니다.

**재시도를 안 하는 이유는요?**
메시지 전송은 되돌릴 수 없습니다. 보냈는지 모르는 상태에서 다시 보내면 같은 말이 두 번 갑니다. 애매하면 멈추고 사람에게 알리는 쪽을 골랐습니다.

**이 작업에서 배운 점은요?**
답장마다 시간과 토큰을 찍어 둔 덕분에 "느리다"가 "20초, 7회, 50.0k"라는 숫자가 됐고, 무엇을 고칠지 바로 보였습니다.
