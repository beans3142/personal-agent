# 구글 캘린더와 드라이브 연결

> 2026-11-14 · 커밋은 산출물 참고 · 서버에 이미 있던 구글 로그인으로 Apps Script를 만들어, 일정 만들기·조회와 PC 파일의 드라이브 링크를 모델 호출 없이 처리

## 무엇이 문제였나

"일정 등록해줘"를 처리할 도구가 없었다. PC 파일을 보내는 방법도 Discord 첨부(10MB 이하)나 24시간 다운로드 링크뿐이었다. 소유자는 구글 드라이브 링크로 받기를 원했다. 서버의 ChatGPT 데스크톱 로그인용 브라우저 프로필에 소유자 구글 계정 로그인이 이미 남아 있었다.

## 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| Google Cloud 프로젝트 + OAuth 클라이언트 | 공식 API | 콘솔에서 프로젝트·동의 화면·클라이언트를 만들어야 하고, 테스트 모드면 갱신 토큰이 7일 뒤 만료돼 버림 |
| 소유자 계정의 Apps Script 웹 앱 | 소유자 권한으로 실행, 토큰 관리 없음, 서버의 기존 구글 로그인으로 만들 수 있음 | 고름 |
| Gemini CLI(agy)에 맡기기 | 문서·시트도 말로 시킬 수 있음 | 서버에 설치돼 있지 않고 캘린더·드라이브 직접 조작 여부를 확인하지 못함. 요청마다 모델 호출이 붙어 버림 |
| 캘린더 웹 화면 조작 | 설정이 적음 | 화면이 바뀌면 깨지고 느려 버림 |

## 바꾼 것

- `deploy/google_bridge.gs`: `doPost`가 공유 키를 확인한 뒤 `calendar_list`, `calendar_add`, `drive_upload` 세 가지만 처리한다. 파일은 드라이브의 `Daevis` 폴더에 들어간다. 서버에는 키를 넣은 사본만 두고, 공개 저장소에는 자리표시자만 둔다.
- 서버 브라우저 프로필로 Apps Script 프로젝트를 만들고 웹 앱(내 계정으로 실행, 모든 사용자 접근)으로 배포했다. 접근은 키로 막는다.
- `agent/google_bridge.py`: 시간대가 없는 시각은 한국 시각으로 본다. 종료 시각을 생략하면 1시간, 종일 일정은 날짜만 보낸다. 잘못된 입력은 구글을 부르기 전에 거절한다. 업로드는 30MB까지다.
- `agent/pc_tools.py` `pc_drive_upload`: PC 파일을 받아 드라이브에 올리고 링크를 돌려준다. 받은 파일은 Discord 첨부 폴더가 아닌 곳에 잠시 두었다가 지운다.
- `agent/mcp_server.py`: 키와 주소가 있을 때만 도구를 등록한다. 서버 허용 목록에 세 도구를 추가했다.

## 확인한 것

- 관련 테스트: `tests/test_google_bridge.py` 10개 추가, `test_mcp_server`·`test_progress`·`test_pc_tools`와 합쳐 69개 통과(전체 테스트는 돌리지 않음).
- 실서버 웹 앱: 틀린 키는 `forbidden`, 맞는 키로 일정 조회 성공.
- 실서버 도구 직접 호출 1회씩:
  - PC 문서 폴더의 시험 파일을 드라이브에 올려 링크를 받았다. 서버 임시 폴더에는 파일이 남지 않았다.
  - 시험 일정 하나를 만들고 같은 날 조회에서 그 일정이 보였다.
- 배포 뒤 게이트웨이 서비스가 active이고 Discord에 다시 접속했다.

## 틀린 지점

- 처음에는 소유자 PC의 브라우저 창에서 구글 로그인을 하게 했다. 서버에 이미 로그인이 있다는 소유자 설명을 먼저 확인했어야 했다.
- 배포 화면 자동화를 여러 번 다시 시작하면서 구글 본인 확인 알림을 소유자 폰에 여러 번 보냈다. 확인 화면의 숫자를 처음부터 읽어 오도록 만들었어야 했다.
- 에디터에 코드를 타이핑하듯 넣었더니 자동 들여쓰기가 섞였다. 붙여넣기로 바꾸고 다시 읽어 원본과 같은지 비교했다.
- PC를 공유기 뒤로 옮기면서 공인 IP가 바뀌어 서버 SSH 허용 주소도 바꿔야 했다.

## 아직 모르는 것

- 실제 문장 요청("일정 등록해줘", "드라이브 링크로 줘")을 모델이 이 도구로 처리하는지는 아직 보지 않았다. 시험 시점에 ChatGPT 사용량 한도에 걸렸다. 한도가 풀린 뒤 같은 문장으로 확인한다.
- 드라이브에 올라간 파일 내용을 열어 원본과 비교하지는 않았다. 업로드 결과의 성공 응답과 링크만 확인했다.
- 구글이 이 미검증 앱의 권한을 얼마나 유지하는지 모른다. 권한 화면에 "곧 작동이 중지될 수 있다"는 안내가 있었다.

## 이어서: 큰 파일은 PC가 드라이브로 직접 올린다

### 무엇이 문제였나

첫 구현은 PC 파일을 서버로 받은 뒤 Apps Script 요청 하나에 base64로 실어 보냈다. Apps Script 요청 한도 때문에 30MB까지만 됐다. 소유자는 1GB 이상도 원했고, 파일은 데스크톱에만 두고 드라이브로 올리기를 원했다.

### 바꾼 것

- Apps Script에 `drive_token` 동작을 추가했다. 소유자 계정의 짧은 수명 토큰과 `Daevis` 폴더 ID를 서버에 돌려준다. 같은 배포 주소에 새 버전으로 배포했다.
- `GoogleBridge.drive_session`: 서버가 드라이브에 파일을 먼저 만들고(링크가 이때 정해진다) 이어 올리기(resumable) 주소를 연다. 토큰은 서버 밖으로 나가지 않는다.
- `pc_drive_upload`: PC에서 파일 크기를 확인하고, 업로드 주소를 넣은 PowerShell을 PC에서 백그라운드로 띄운다. PC는 파일을 4MB씩 읽어 그 주소로 흘려보내고 진행 상황을 작은 JSON에 적는다. 서버는 최대 150초 동안 진행을 확인한다. 그 안에 안 끝나면 링크와 함께 "PC가 계속 올리는 중"으로 답한다. 업로드 스크립트는 끝나면 스스로 지운다.
- 한도는 10GB로 두었다(드라이브 자체 한도보다 훨씬 작게 둔 안전선).

### 확인한 것

- 관련 테스트: `tests/test_google_bridge.py` 14개, `test_pc_tools`·`test_mcp_server`·`test_progress`와 합쳐 73개 통과(전체 테스트는 돌리지 않음).
- 실서버 1회: PC의 1GB 파일을 104.8초에 올렸다. 서버 임시 폴더에는 파일이 없었다. 드라이브의 크기(1,073,741,824바이트)와 MD5가 PC 파일의 MD5와 같았다. 시험 파일은 PC에서 지우고 드라이브에서는 휴지통으로 보냈다.
- 첫 소형 파일 업로드도 드라이브에서 내용을 읽어 PC 원본과 같은 것을 확인했다.
- 실제 문장 요청 1회씩(ChatGPT 한도 중이라 Claude 대체 경로로 실행): "내일 오후 3시 치과 일정 등록해줘"는 11/15 15:00~16:00 일정을 만들었다. "문서 폴더의 시험 파일 구글 드라이브 링크로 줘"는 52.2초에 링크를 답했다.

### 틀린 지점

- PowerShell 문자열 안의 작은따옴표 처리를 시험에서 한 번만 이스케이프된 값으로 기대했다. 실제로는 스크립트 안의 리터럴이 다시 명령 리터럴 안에 들어가므로 두 번 이스케이프되는 것이 맞다.

### 아직 모르는 것

- 150초 안에 안 끝나는 큰 파일은 업로드가 끝났다는 알림이 따로 가지 않는다. 링크는 바로 주지만, 다 올라가기 전에 열면 빈 파일로 보일 수 있다.
- PC가 업로드 중에 꺼지거나 잠들면 이어 올리지 않는다.

## 셀프 인터뷰

**웹 앱을 "모든 사용자"로 연 것은 위험하지 않나요?**
주소와 키를 둘 다 알아야 동작합니다. 키가 틀리면 아무것도 하지 않고 `forbidden`만 돌려줍니다. 키는 서버 `.env`에만 있습니다.

**왜 드라이브 권한이 "모든 파일"로 잡혔나요?**
Apps Script의 `DriveApp`이 넓은 권한을 요구합니다. 스크립트가 하는 일은 `Daevis` 폴더에 파일을 만드는 것뿐이지만, 권한 범위 자체는 넓습니다.

**Discord 첨부나 24시간 링크와 무엇이 다른가요?**
드라이브 링크는 만료되지 않고 소유자 구글 계정에서 바로 열립니다. 파일이 서버를 거치지 않아 서버 디스크·대역폭을 쓰지 않습니다.

**PC에 토큰을 주지 않는 이유는요?**
드라이브 토큰은 소유자 드라이브 전체에 접근합니다. PC에는 파일 하나에만 쓸 수 있는 업로드 주소만 보냅니다.
