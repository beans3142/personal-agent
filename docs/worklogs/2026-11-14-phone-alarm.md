# 대비스가 폰에 알람 맞추기

> 2026-11-14 · 커밋은 산출물 참고 · Galaxy 앱이 알람 작업을 받아 정확한 시각에 한 번 울린다. 서버 Android에서 큐 등록부터 울림·끄기까지 1회 확인

## 무엇이 문제였나

"일요일 4시 알람 맞춰줘"를 처리할 수 없었다. 기존 `phone_alarm`은 Termux 폰에서 소리를 즉시 한 번 내는 기능이라 예약 알람이 아니었다. Galaxy 앱은 대화 화면일 뿐 서버 작업을 받지 않았다. 중계 서버에 등록된 폰 3대는 모두 등록이 해제된 상태였다.

## 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| 시계 앱 알람 등록 인텐트(`SET_ALARM`) | 기본 시계 앱에 보인다 | 시와 분만 받아 날짜를 정할 수 없고, 앱이 뒤에 있을 때는 화면을 띄울 수 없어 버림 |
| Termux 노드에 예약 알람 추가 | 서버 코드 재사용 | 소유자 폰에 Termux가 설치돼 있지 않아 버림 |
| Galaxy 앱이 알람 작업을 받아 `AlarmManager.setAlarmClock`으로 등록 | 날짜까지 정확, 잠금·절전 중에도 울림 | 고름 |

## 바꾼 것

- 중계 서버(`agent/device_nodes.py`): `phone_alarm_at` 작업을 추가했다. 미래 31일 안의 시각과 60자 이하 이름만 받는다. 다른 작업은 5분 뒤 사라지지만 이 작업은 알람 시각까지 남는다. 앱이 알람 작업만 가져가도록 `/poll`에 작업 종류 필터를 추가했다. 그래서 전화 작업과 섞이지 않는다.
- `agent/pc_control.py`: 폰을 등록하면 메인 에이전트가 그 폰에 알람을 보낼 권한을 함께 준다. 대상 이름 `phone`은 가장 최근에 등록된 폰을 뜻한다.
- `agent/phone_alarm.py` `phone_alarm` 도구: 한국 시각을 받아 중계 서버에 작업을 넣는다. 결과에는 "아직 폰에 등록된 것은 아니다"를 함께 돌려준다.
- Galaxy 앱:
  - 앱을 열 때와 15분마다 알람 작업을 가져온다.
  - 정확한 알람으로 등록하고, 결과를 서버에 알린다.
  - 그 시각에 알람 소리 채널로 끄기 전까지 반복해 울린다.
  - 재부팅 뒤에도 알람을 다시 건다.
  - 앱을 열 때 알림 권한을 묻는다.

## 확인한 것

- 관련 테스트: `tests/test_phone_alarm.py` 15개, `test_device_nodes`·`test_pc_control`·`test_phone_call`과 합쳐 126개 통과. 앱 순수 로직 JDK 테스트 25개 통과. 전체 테스트는 돌리지 않았다.
- CI로 서명된 APK를 빌드했다(약 100KB). 에뮬레이터 실행 확인도 CI에서 돈다.
- 서버 Android(ReDroid, Android 13)에서 1회:
  - 시험용 등록 코드로 앱을 연결했다.
  - 메인 서버에서 `phone_alarm` 도구로 3분 뒤 알람을 넣었다.
  - 앱이 작업을 가져가 정확한 알람(`exactAllowReason=policy_permission`)으로 등록했다.
  - 04:30:00 알람이 04:30:02에 알람 채널 알림으로 떴다. "끄기"를 누르자 알림이 사라졌다.
  - 서버 작업 결과는 `succeeded`, `{"scheduled": true, "exact": true}`였다.
  - 시험 뒤 시험용 등록은 해제하고 앱은 지웠다.

## 틀린 지점

- 처음에는 Galaxy 앱이 이미 서버 작업을 받는다고 생각했다. 실제로는 전화 작업도 Termux 스크립트가 받았고, 앱은 대화만 했다.
- 중계 서버 코드가 저장소와 다른 버전이었다. 그래서 파일을 통째로 올리지 않고, 바꿀 부분만 기준 문자열로 확인한 뒤 고쳤다.

## 아직 모르는 것

- 실제 소유자 폰(Galaxy A33)에서는 아직 시험하지 않았다. 삼성 절전 설정이 15분 확인을 늦출 수 있다. 알람이 이미 등록된 뒤에는 정확한 알람이라 영향이 적다.
- 알림 권한을 예전에 거절했다면 앱이 다시 묻지 않는다. 그 경우 설정에서 직접 켜야 한다.

## 셀프 인터뷰

**앱이 15분마다만 확인하면 알람을 놓치지 않나요?**
작업은 알람 시각까지 서버에 남아 있습니다. 앱이 그 전에 한 번만 가져가면 됩니다. 가져간 뒤에는 폰이 알람을 직접 울리므로 서버나 네트워크와 상관없습니다.

**왜 전화 작업과 같은 등록을 쓰나요?**
폰 하나에 등록 하나로 관리하기 위해서입니다. 대신 앱은 알람 작업만 가져가고, 전화 작업은 그대로 남겨 둡니다.

**왜 시계 앱에 등록하지 않았나요?**
안드로이드의 알람 등록 인텐트는 날짜를 받지 않습니다. 앱이 뒤에 있을 때는 시계 앱을 띄울 수도 없습니다.

- 테스트: `tests/test_phone_alarm.py`, `android/test/LogicTest.java`
