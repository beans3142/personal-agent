# ChatGPT 한도에 걸리면 Claude가 이어받는다

> 2026-11-08 · 도구 작업 모델이 ChatGPT 하나뿐이라 한도가 걸리면 87초 기다린 뒤 실패만 알렸다. 이제 아무 도구도 실행되지 않은 경우에만 같은 요청을 Claude로 한 번 더 처리한다(서버 실측 2회 성공)

## 무엇이 문제였나

Discord에서 도구가 필요한 요청을 보냈더니 진행 메시지가 "요청을 이해하는 중…"에 87.1초 동안 머물렀다. 그 뒤에 "모델 사용량 한도에 걸려 답변을 만들지 못했어요."로 바뀌었다. 요청은 처리되지 않았다.

## 원인

- 도구가 필요한 요청은 Hermes가 처리하고, Hermes 모델은 ChatGPT(Codex 로그인) 하나만 설정돼 있었다. Claude는 도구 없는 일반 대화에서만 쓰였다.
- ChatGPT Plus 사용량이 다 떨어져 HTTP 429 `usage_limit_reached`가 났다. Hermes는 같은 호출을 3번 재시도한 뒤 `max_retries_exhausted`로 끝냈다. 87초는 이 재시도 대기 시간이다.
- 실패 안내 자체는 동작했다. 다만 어느 모델의 한도인지, 언제 풀리는지는 알려 주지 않았다.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| Claude CLI에 같은 MCP 설정을 붙여 새 실행기를 만든다 | Claude Code 기능을 그대로 쓴다 | 승인, 영수증, 단계 한도 같은 Hermes 쪽 장치를 다시 만들어야 해서 버림 |
| Hermes의 제공자만 Anthropic으로 바꿔 한 번 더 실행한다 | 도구, 승인, 영수증, 한도 처리를 그대로 쓴다. Hermes가 Claude 로그인 토큰(`sk-ant-oat`)을 지원한다 | 고름 |
| Hermes 자체 대체 제공자 설정(`hermes fallback add`) | 설정만 바꾸면 된다 | 도구가 이미 실행된 뒤에도 넘어갈 수 있어 카톡 같은 전송이 두 번 나갈 위험이 있어 버림 |

## 바꾼 것

- `HermesRunner.run`이 한도 오류를 받으면 아래 조건을 모두 확인한 뒤에만 Claude로 한 번 다시 실행한다.
  - 실패 이유가 `usage_limit_reached` 또는 `model_rate_limited`다.
  - 실행된 도구가 0개다.
  - 카톡 화면이나 카톡 도구를 건드리지 않았다.
  - Claude 토큰을 Parameter Store에서 읽을 수 있다.
- 재실행은 요청 ID와 만료 시각을 새로 받는다. 승인 절차와 도구 정책은 첫 실행과 같다.
- 워커는 `DAEVIS_HERMES_PROVIDER=anthropic`이면 `claude-sonnet-5-5`를 쓴다. Claude 토큰은 Hermes를 불러온 직후 환경 변수에서 지운다. MCP 도구 프로세스에는 넘어가지 않는다.
- 한도 안내 문구가 "ChatGPT 사용량 한도"라고 밝히고 풀리는 시각(KST)을 붙인다. Claude로 처리한 답의 꼬리말에는 "ChatGPT 한도로 Claude가 처리 (ChatGPT 11/12 16:57 복구)"가 붙는다.
- Claude 재실행까지 실패하면 두 실패를 함께 알린다.

## 확인한 것

- 관련 테스트 10개를 먼저 추가했다(폴백 1회, 도구 실행 뒤 폴백 안 함, 카톡 화면 뒤 폴백 안 함, 토큰 없음, 토큰 조회 실패, Claude도 실패, 해제 시각 표기, 토큰 비전달, 제공자 선택). 전체 테스트 744개 통과.
- 서버에서 ChatGPT 한도가 걸린 상태로 실제 실행 2회:
  - 도구 없는 질문: Claude가 답함, 31.5초, 모델 호출 1회.
  - `tool_search`를 쓰는 질문: Claude가 도구 2회를 쓰고 답함, 30.2초, 모델 호출 3회.
- 두 번 모두 읽기 전용 모드로 돌렸다. 카톡 전송 같은 쓰기 작업은 폴백 경로에서 실제로 해 보지 않았다.

## 틀린 지점

- 처음에는 Claude 토큰을 Hermes를 불러오기 전에 환경 변수에서 지웠다. Hermes는 불러오는 도중 같은 스크립트를 새 프로세스로 다시 띄운다. 그래서 제공자 설정이 사라져 두 번째 실행도 ChatGPT로 나갔다. 불러온 직후에 지우도록 옮겼다.
- 해제 시각을 오류 문구에서 정규식으로 찾으려 했다. 실제 응답에는 문구에 시각이 없고 `failure_resets_at` 필드에 들어 있었다. 이 필드를 먼저 읽는다.

## 아직 모르는 것

- 한도에 걸린 첫 실행이 재시도에 약 40~87초를 쓴다. Claude로 넘어가기 전 기다림을 줄이려면 Hermes 재시도 횟수를 조정해야 한다. 아직 손대지 않았다.
- Claude 구독 한도에 걸렸을 때의 문구는 실제로 보지 못했다.

## 셀프 인터뷰

**왜 도구가 하나라도 실행됐으면 넘기지 않나요?**
첫 실행이 카톡을 이미 보냈을 수 있습니다. 같은 요청을 다른 모델로 다시 돌리면 메시지가 두 번 나갈 수 있어서, 아무 것도 실행하지 않았다는 것이 확실할 때만 넘깁니다.

**Claude 토큰이 도구 쪽으로 새지 않는다는 건 어떻게 보장하나요?**
MCP 도구 프로세스에 넘기는 환경 변수는 허용 목록으로만 고릅니다. 토큰은 그 목록에 없고, 워커가 Hermes를 불러온 직후 자기 환경에서도 지웁니다. 허용 목록 테스트를 추가했습니다.

**이 작업에서 배운 점은요?**
화면에 멈춘 것처럼 보이던 상태가 실제로는 재시도 대기였습니다. 증상만 보고 "실패 안내가 없다"고 판단하기 전에 Discord에 실제로 남은 메시지를 먼저 확인해야 했습니다.
