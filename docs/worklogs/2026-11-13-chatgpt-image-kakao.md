# ChatGPT로 그린 그림을 Discord와 카톡으로 보내기

> 2026-11-13 · 커밋은 산출물 참고 · 요청 한 번에 그림 생성과 카톡 사진 전송까지, 실서버 2회 92초·119초

## 무엇이 문제였나

"펭귄 그림 하나 만들어서 나한테 카톡으로 보내줘" 같은 요청을 처리할 도구가 없었다. 대비스는 글자 카톡만 보낼 수 있었고, 그림을 만드는 수단도 없었다. 이미지 생성 API를 따로 쓰면 요금이 붙는다. 그런데 서버에는 소유자 구독으로 로그인한 ChatGPT 데스크톱 앱이 이미 떠 있었다. 이 앱은 글 답변(`agent/desktop_text.py`)에만 쓰이고 있었다.

## 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| 이미지 생성 API | 호출이 단순하다 | 장당 요금이 붙어 버림 |
| 서버의 ChatGPT 앱을 CDP로 조작 | 구독 안에서 해결, 로그인·화면 잠금(`ui_lock`) 재사용 | 고름 |
| 카톡 공유 인텐트(`ACTION_SEND`)로 사진 보내기 | 화면 단계가 적다 | 공유 화면에서 받는 사람을 다시 골라야 해서 기존 방 확인 절차를 쓸 수 없어 버림 |
| 채팅방 안의 사진 선택 화면 | 글자 전송과 같은 방 확인·잠금·기록을 그대로 쓴다 | 고름 |

## 바꾼 것

- `agent/chat_image.py` `image_generate`: 별도 프로세스에서 ChatGPT 앱에 새 대화를 열고 그림을 요청한다. `img[alt^="Generated image"]`가 새로 생기고 주소와 너비가 두 번 연속 같으면 완성으로 본다. 그림 데이터를 PNG로 이번 요청의 outbox에 저장한다. 게이트웨이가 outbox의 PNG를 요청한 Discord 채널에 붙이므로 Discord 전송은 따로 만들지 않았다.
- `agent/kakao_image.py` `send_image`: 사진 선택 화면은 썸네일만 보여 줘서 어느 것이 방금 만든 그림인지 알 수 없다. 그래서 Android의 전용 앨범(`Pictures/Daevis`)에서 기존 파일을 지우고 이번 그림 하나만 넣는다. 미디어 색인에 그 파일 하나만 있는지 확인하고, 선택 화면에서도 앨범 이름과 개수 1, 썸네일 1개를 확인한 뒤 고른다. 보낸 뒤에는 같은 방에 내가 보낸 사진 말풍선이 새로 생겼는지 확인한다.
- `agent/kakao_watch.py`: 방 찾기·잠금·전송 기록을 `_deliver_once`로 묶었다. 글자(`send_once`)와 사진(`send_image_once`)이 같은 절차를 쓴다. 사진은 파일 해시로 같은 요청의 중복 전송을 막는다. 결과가 애매하면 기존과 같이 다음 전송을 막는다.
- `kakao_send_image` 도구는 이번 요청 outbox에 있는 `image-<10자리>.png`만 받는다. 다른 경로는 `KAKAO_IMAGE_NOT_FOUND`로 거절한다.
- 진행 표시에 "이미지 만드는 중", "카톡으로 사진 보내는 중"을 추가했다. 결과 코드 `KAKAO_IMAGE_SENT`는 "카톡으로 사진을 보냈습니다."로 답한다.

## 확인한 것

- 관련 테스트: `tests/test_chat_image.py` 9개, `tests/test_kakao_image.py` 8개 추가. 바꾸기 전 전체 테스트 1,135개 통과. 등록·문구 변경 뒤에는 관련 파일(`test_mcp_server`, `test_progress`, `test_gateway`, 카톡 테스트)만 다시 돌렸다.
- 실서버, 받는 사람은 나와의 채팅만 사용했다.
  - 도구 직접 호출 1회: 그림 생성 49.4초(1254×1254 PNG), 카톡 사진 전송 22.1초. 화면에서 사진 말풍선을 눈으로 확인했다.
  - 실제 요청 경로(HermesRunner) 2회: 92.4초, 119.1초. 모델이 `image_generate` 다음 `kakao_send_image`를 골랐고 최종 코드는 `KAKAO_SENT`, 문구 수정 뒤 `KAKAO_IMAGE_SENT`였다.
- Discord 첨부는 기존 `send_outbox` 경로를 그대로 탄다. 이번에 실제 Discord 채널로 보내 보지는 않았다.

## 틀린 지점

- 카톡 미디어 패널에 "Permission Settings"가 떠서 권한 문제라고 보고 `pm grant`와 `appops`를 먼저 손댔다. 실제로는 패널의 최근 사진 줄만 그랬고, "Photo" 항목의 선택 화면은 권한 부여 뒤 정상으로 열렸다.
- 처음 열 때 "Show Shared Media" 안내 창이, 원본 화질로 보낼 때 EXIF 안내 창이 한 번씩 뜬다. 첫 시험에서 이 창에 막혔다. 지금은 알려진 제목일 때만 확인 또는 전송 버튼을 누른다.

## 아직 모르는 것

- 실제 Discord 채널에서 첨부가 붙는지는 아직 보지 않았다. 다음 실제 요청에서 확인한다.
- ChatGPT 앱이 그림 대신 질문으로 답하면 시간 초과(180초)로 실패한다. 프롬프트에 "설명 없이 이미지 한 장만"을 붙였지만 몇 번에 한 번 그러는지는 재지 않았다.
- 다른 사람 방으로 보내는 경우는 시험하지 않았다. 방 확인은 글자 전송과 같은 코드라 동작은 같아야 한다.

## 셀프 인터뷰

**선택 화면에서 고른 사진이 방금 만든 그림이라는 걸 어떻게 보장하나요?**
썸네일에는 파일 이름이 없어서 화면만으로는 구분할 수 없습니다. 그래서 전용 앨범에 그 파일 하나만 남기고, 미디어 색인과 선택 화면 양쪽에서 개수가 1인지 확인했을 때만 고르게 했습니다.

**왜 공유 인텐트를 쓰지 않았나요?**
공유 화면에서는 받는 사람을 다시 고르는 단계가 생깁니다. 글자 전송에서 이미 검증한 방 확인 절차(정확한 이름, 방 제목, 인원수)를 다시 만들어야 합니다. 같은 채팅방 안에서 보내면 그 절차를 그대로 씁니다.

**Discord 전송 도구는 왜 따로 없나요?**
게이트웨이가 이미 요청별 outbox의 PNG를 요청한 채널에 붙입니다. 그림을 outbox에 저장하기만 하면 되므로 새 도구를 만들 이유가 없었습니다.
