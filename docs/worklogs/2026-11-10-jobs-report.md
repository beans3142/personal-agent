# 채용 보고서: 경력·병역특례 공고를 거르고 대기업·인턴·부트캠프를 따로 묶는다

> 2026-11-10 · 커밋은 아래 산출물 참고 · 게시된 공고 327건(대기업·공채 37, 인턴 58, 신입 216, 부트캠프 16), 제외 13건

## 무엇이 문제였나

소유자가 채용 보고서에서 짚은 문제는 다섯 가지였다.

- 원문이 404인 공고 링크가 그대로 보였다.
- 산업기능요원 공고와 경력직 공고가 섞여 있었다.
- 대기업 공채가 거의 보이지 않았다.
- 출처가 적었고 인턴·부트캠프가 없었다.
- 카드에 업무와 자격 요건이 없어서 내용이 부실했다.

## 왜 그런 일이 생겼나

- 404·410 응답을 "접근 실패"로만 표시하고 마감으로 처리하지 않았다.
- 예전에 직접 조사해 넣은 공고는 매일 상태만 다시 확인하고, 경력 조건 필터를 다시 거치지 않았다.
- "지원 예정" 상태의 공채는 보고서 대상에서 빠져 있었다. 대기업 공채를 모아 주는 출처도 없었다.
- 원티드·점핏은 상세 내용을 받아 놓고도 화면에 쓰지 않았다.

## 바꾼 것

보고서 수집·렌더링 코드는 공개 저장소 밖(`agent/private/brief/`)에 있어서, 여기에는 동작만 적는다.

- **같은 기준을 모든 공고에 적용한다.** 빼는 공고는 다음과 같다.
  - 병역특례(산업기능요원·전문연구요원) 공고
  - "N년 이상" 경력 요구, 연차 지정 공고
  - 해외 근무 공고
  - 백엔드와 거리가 먼 직무(임베디드·C++·로보틱스 등)
  - 404·410 원문(마감으로 처리)
- **출처를 추가했다.** 링커리어(대기업·공채, 인턴, 부트캠프·교육)와 사람인 신입 목록이다. 같은 공고가 여러 사이트에 있으면 카드 하나로 합친다.
- **카드 내용을 채웠다.** 주요 업무, 자격 요건, 우대 사항을 각 세 줄까지 보여주고, 공고 기술 중 소유자가 써 본 것을 표시한다. 이 비교는 모델 호출 없이 코드로 한다.
- **페이지 구성을 바꿨다.** "대기업·공채 / 인턴·채용연계형 / 신입·경력 무관 / 부트캠프·교육" 네 묶음으로 나눴다.
  - 겹치는 기술이 많은 순, 그다음 마감이 가까운 순으로 정렬하고 D-n을 붙인다.
  - 맨 아래에 제외한 공고와 이유를 보여준다.

## 확인한 것

- 비공개 보고서 테스트 58개가 로컬에서 통과했다. 서버에는 pytest가 없어 서버에서는 실행하지 않았다.
- 서버에서 보고서 생성과 Vercel 배포를 알림 없이 실행했고, 배포 상태는 deployed였다.
- 실제 `/jobs/` 페이지를 확인했다.
  - 네 묶음이 보인다.
  - D-n 표시 47개, 제외 목록 13건이 보인다.
  - 문제였던 병역특례 당근 공고는 제외 목록에 있다.
  - 모바일(375px)과 데스크톱에서 가로로 밀리지 않는다. 문서 전체 너비는 441px로 계산되지만, 실제 가로 스크롤은 0이었다.

## 아직 모르는 것

- SK하이닉스 공고가 없는 이유. 오늘 기준 링커리어 목록에 없었지만, 실제로 채용을 안 하는 것인지 그 사이트에 안 올라온 것인지는 확인하지 못했다.
- "백엔드와 거리가 먼 직무" 기준이 소유자가 원하는 범위와 맞는지.
- 잡플래닛과 직행은 넣지 않았다.
  - 잡플래닛: 비밀번호 로그인이 필요하고, 로그인 없이 쓰는 API는 403이었다.
  - 직행: robots.txt가 API 수집을 막는다.

## 셀프 인터뷰

1. **예전에 직접 넣은 공고까지 다시 거르는 이유는요?** 처음 넣을 때 조사 메모에 "경력 요건 미충족"이라고 적어 놓고도 계속 보여주고 있었습니다. 기준이 출처마다 다르면 보고서를 믿을 수 없어서, 모든 공고에 같은 필터를 적용했습니다.
2. **로그인이 필요한 사이트는 왜 빼나요?** 비밀번호를 대신 넣는 자동화는 만들지 않습니다. 또 사이트가 robots.txt로 막은 수집은 하지 않습니다.
3. **모델 호출이 늘었나요?** 아닙니다. 기술 비교와 분류는 모두 코드로 합니다.

## 이어서: 한 페이지로 합치고 추천 공고만 요약한다

### 무엇이 문제였나

네 묶음으로 나눈 화면은 카드마다 배지, 마감·근무지·상태, 요건 목록이 다 펼쳐져서 한 장이 화면 하나를 차지했다. 날짜별로 페이지를 새로 만들다 보니 어제 페이지의 D-day는 그대로 멈춰 있었다. 소유자는 페이지 하나에 마감 가까운 순으로 놓고 새 공고를 표시하자고 했고, 직무에 잘 맞는 공고만 요약을 붙여 달라고 했다.

### 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| 날짜별 페이지 유지, 매일 다시 생성 | 기록이 남는다 | 같은 공고가 매일 복제되고, 배포가 밀리면 D-day가 틀린다. 버림 |
| `/jobs/` 한 페이지 + 브라우저에서 D-day 계산 | 배포가 하루 밀려도 D-day가 맞고 지난 공고가 저절로 숨는다 | 고름 |
| 모든 공고를 모델이 읽고 적합도 판단 | 판단이 정교하다 | 하루 300건 이상이라 호출이 30배쯤 는다. 버림 |
| 코드로 적합 공고를 고르고 그 10건만 모델 요약 | 하루 모델 호출 1회, 같은 공고는 캐시 | 고름 |

### 바꾼 것

- `/jobs/` 한 페이지만 만든다. 예전 날짜 주소 `/jobs/YYYY-MM-DD/`는 `/jobs/`로 넘긴다. Discord 알림도 `/jobs/`를 가리킨다.
- 공고를 마감 가까운 순으로 놓고, 같은 날이면 그날 처음 본 공고를 앞에 둔다. 상시 채용은 끝에 둔다.
- 카드에는 회사, D-day, 제목, 지역·고용형태·경력·출처 한 줄, 기술 칩만 보이게 했다. 업무·요건과 확인 기록은 접어 두었다.
- 탭(전체, 추천, 신규, 대기업·공채, 인턴, 신입, 부트캠프)으로 거르고, 30건씩 "더 보기"로 늘린다.
- 카드마다 마감일과 처음 본 날짜를 data 속성으로 넣는다. 브라우저가 오늘 날짜로 D-day를 다시 계산해서 지난 공고를 숨기고, 3일이 지난 공고의 NEW 표시를 지운다.
- 추천은 코드가 고른다. 써 본 기술이 3개 이상 겹치고 업무·요건이 읽히는 공고 중 최대 10건이다. 이 10건만 Claude CLI에 한 번에 보내 하는 일, 요건, 겹치는 점, 확인할 점을 한 줄씩 받는다. 결과는 공고 내용 해시로 캐시한다.

### 확인한 것

- 비공개 보고서 테스트 60개가 로컬에서 통과했다. 추천 선정, 요약 캐시(두 번째 호출 0회), 응답 파싱 재시도, 한 페이지 정렬을 포함한다.
- 서버에서 보고서 생성과 Vercel 배포를 알림 없이 두 번 실행했고, 두 번 모두 deployed였다.
- 실제 `/jobs/`를 브라우저로 열어 확인했다. 데스크톱(1280px)과 모바일(390px)에서 다음을 봤다.
  - 응답 200, 가로 넘침 0, 페이지 오류 0.
  - 추천 요약 10개가 보인다.
  - 처음에 카드 40장(추천 10 + 목록 30)이 보인다.
  - 맨 앞은 D-1 공고다.
  - 부트캠프 탭은 16장이다.
  - `/jobs/2026-11-09/`는 `/jobs/`로 넘어간다.
- 같은 페이지 파일을 브라우저 시계를 11/15로 바꿔 열었다. 공고 수가 324건에서 310건으로 줄었고, 맨 앞이 "오늘 마감"으로 바뀌었고, NEW 표시는 0개였다.

### 틀린 지점

- 첫 서버 실행에서 요약이 `JSONDecodeError`로 실패했다. 응답에서 첫 `[`부터 마지막 `]`까지를 정규식으로 잘라 읽었기 때문에, 앞뒤 문장에 대괄호가 섞이면 깨지는 구조였다. 첫 번째 유효한 JSON 배열을 찾아 읽게 바꾸고, 실패하면 한 번 다시 묻게 했다.
- 같은 날 다시 실행했더니 이전 실행의 오류 값이 보고서 데이터에 남았다. 보고서 데이터가 전날 파일을 이어 쓰는 구조라서, 실행마다 그 값을 지우게 했다.

### 아직 모르는 것

- 새 출처를 오늘 처음 모아서 "신규"가 260건이다. 실제로 새로 올라온 공고만 표시되는지는 내일 정기 실행 뒤에 확인한다.
- 추천은 기술 이름이 맞는지만 본다. 기술명 없이 업무만 적은 공고는 추천에서 빠질 수 있다.

### 셀프 인터뷰

1. **적합도를 판단하려면 결국 다 읽어야 하지 않나요?** 수집 단계에서 이미 받아 둔 요건 글로 코드가 기술 이름을 셉니다. 모델은 그렇게 추린 10건만 읽어서 하루 1회 호출이면 됩니다.
2. **왜 D-day를 서버가 아니라 브라우저에서 계산하나요?** 공고 수집은 하루 한 번인데 페이지는 언제 열지 모릅니다. 마감일을 데이터로 넣고 보는 날짜로 계산하면, 배포가 밀려도 표시가 틀리지 않습니다.
3. **날짜별 기록을 없애도 되나요?** 채용 공고는 지난 목록을 다시 볼 일이 거의 없고, 공고 추적 파일에 처음 본 날짜와 확인 기록이 남습니다. 예전 주소는 깨지지 않게 넘깁니다.

## 2026-11-11: 내 기준 점수, 확인 떠넘기기 제거, 나머지 보고서 개인화

### 무엇이 문제였나

소유자가 실제 페이지를 보고 네 가지를 짚었다.

- 업데이트가 안 된 것처럼 보였다. 오늘 수집은 돌았지만, 전날 출처를 처음 모으면서 258건이 한꺼번에 "처음 본 공고"로 기록됐다. 그래서 오늘 새로 들어온 3건이 NEW 표시 사이에 묻혔다.
- 요약이 "담당 업무 확인 필요", "Node.js 경험 확인 필요"처럼 확인을 독자에게 넘겼다. 요약 모델에게 업무·요건 세 줄만 주고 공고 전문과 기업 지원 페이지를 주지 않았기 때문이다. 소유자가 써 본 기술 목록도 고정 목록이라 포트폴리오와 어긋났다.
- 마감 순 정렬은 무엇이 나에게 맞는지 보여 주지 않았다.
- 인턴 기간, 모집 기간, 전형 절차(코딩테스트 언어, AI 면접, 컬처핏, 면접 차수)가 카드에 없었다.

### 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| 잡플래닛 평점 | 소유자가 원한 출처 | 회사 페이지와 검색 모두 자동 접근에 403. 버림 |
| 블라인드 공개 회사 페이지 | 평점·워라밸·급여복지·평균 연봉·설립 연도가 로그인 없이 보인다 | 회사당 14일 캐시, 하루 최대 120곳, 동시 3개로 고름 |
| 모델이 모든 공고의 적합도 채점 | 정교하다 | 하루 300건 이상이라 호출이 크게 는다. 버림 |
| 기존 career 플러그인의 포트폴리오 대조를 점수에 재사용 | `career_fit` 도구와 보고서가 같은 기준으로 판정한다 | 고름 |

### 바꾼 것

- 공고마다 100점 점수를 붙인다. 모두 코드로 계산한다.
  - **직무 50**: 포트폴리오 대조. `career.py`에 `assess()`를 분리해 `career_fit`과 같이 쓴다. 필수 기술 충족률, 직무명, B2B 계정·권한 유형, 겹친 기술 수를 반영하고, JVM 없는 언어 요구·기졸업자만·어학 성적 요구·없는 필수 기술은 감점한다. 직무명이 백엔드·플랫폼·웹이 아니면 28점을 넘지 않는다.
  - **회사 30**: 규모(IT 대기업 > 대기업 > 스타트업 > 중견 > 공공·금융, 소유자 선호 순서)에 블라인드 평점·워라밸·평균 연봉을 더한다.
  - **거리 20**: 서울·경기·원격 20, 인천 15, 미확인 10, 그 밖 5.
- 연봉이 3,600만원 이하로 적힌 공고와 교대·야간·자차 필수 근무는 뺀다.
- 페이지는 이번 수집에서 처음 찾은 공고를 맨 위에, 나머지를 점수 순으로 둔다. 2026-11-10 첫 수집분은 신규로 치지 않는다.
- 카드에 점수와 세 항목 막대, 회사 규모·블라인드 평점·워라밸, 겹친 기술(초록)과 없는 필수 기술(빨강 테두리), 전형, 모집 기간, 인턴 기간을 넣었다.
- 전형은 단계 이름 사전으로 순서대로 뽑는다(예: 지원서 접수 → TEST 전형 → 1차 면접 → 코딩 테스트 → 2차 면접 → 최종합격). 코딩테스트 옆에 적힌 언어도 붙인다.
- 추천 10건의 요약에 공고 전문과 기업 지원 페이지 글을 함께 넘긴다. 써 본 기술 목록은 포트폴리오 묶음에서 읽는다. "확인 필요" 표현은 프롬프트에서 막고, 응답에 남아도 지운다.
- 대비스 채팅에서 쓸 읽기 도구 `job_board`를 비공개 플러그인에 추가했다(점수 상위, 이번 수집 신규, 7일 안 마감).
- 나머지 보고서도 같은 프로필로 개인화했다.
  - 일간·주간 트렌드와 기술 블로그는 항목마다 "나와의 연결"(써 본 기술, 관심 영역)을 붙이고 가까운 순으로 정렬한다.
  - 주간 페이지의 항목 링크가 같은 주간 페이지로 돌아가던 버그를 원문 링크로 고쳤다.
  - 행사는 채용처럼 한 페이지로 만들고 점수(관련 50, 거리 20, 비용 15, 일정 15)로 정렬한다. 30일 안의 행사를 8건이 아니라 최대 30건 모은다. 행사 페이지 본문에서 "일시 Date 11월 19일" 같은 날짜를 읽는다.
  - 기술 해설 프롬프트에서도 "확인 필요"류 표현을 금지했다.

### 틀린 지점

- 처음 전형 추출은 구분자(>, →)로 나누는 방식이었다. CJ 계열처럼 띄어쓰기로 이어 쓴 공고에서는 문장이 통째로 들어갔다. 단계 이름 사전으로 순서대로 찾는 방식으로 바꿨다.
- "하나 이상 택일" 줄에서 다른 항목이 충족되면 Go 같은 미경험 기술도 초록 칩으로 표시됐다. 충족 목록에서 택일 항목을 뺐다.

### 아직 모르는 것

- 블라인드 회사명과 공고의 회사명이 다르면(예: 영문 표기, 계열사) 회사 정보가 비어 12점 기본값을 받는다. 이름 매칭 실패율은 아직 재지 않았다.
- `job_board`, `career_*` 도구를 대비스 채팅에서 쓰려면 서버 `.env`의 도구 허용 목록과 `DAEVIS_PROFILE=prod` 설정, Hermes 재시작이 필요하다. 이 변경은 소유자 승인을 기다린다.

### 셀프 인터뷰

1. **점수는 모델이 매기나요?** 아닙니다. 포트폴리오 대조, 회사 규모, 거리는 모두 코드로 계산합니다. 모델은 점수 상위 10건을 요약할 때만 씁니다.
2. **잡플래닛 대신 블라인드를 쓴 이유는요?** 잡플래닛은 자동 접근에 403을 돌려줍니다. 블라인드는 로그인 없이 공개된 회사 페이지에 평점과 워라밸이 있습니다. 회사당 14일 캐시와 하루 최대 120곳으로 호출을 제한했습니다.
3. **"확인 필요"를 왜 금지했나요?** 대부분 시스템이 직접 읽을 수 있는 내용이었습니다. 원문 전체와 지원 페이지를 넘기고, 정말 없는 정보만 "공고·지원 페이지에 없음"으로 쓰게 했습니다.
