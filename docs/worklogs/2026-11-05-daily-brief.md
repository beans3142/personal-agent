# 채용 브리핑을 저장소 밖에 두고 고정 주소로 보낸다

> 2026-11-05 · 커밋 전 · 브리핑 페이지는 공개 저장소에 한 줄도 올리지 않고, 로그인 없이 열리는 고정 주소 1개로 DM에 보냈다(실제 배포 1회 확인)

## 무엇이 문제였나

매일 채용 공고, 대기업 채용 동향, 부트캠프 모집, 업계 소식을 모아 보는 브리핑 페이지가 필요했다. 조건은 세 가지였다. 설치 없이 링크로 바로 열릴 것, 내용이 개인정보라 공개 저장소에 파일이나 코드로 남지 않을 것, 게임 서버는 전원 담당으로만 둘 것.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| 공개 저장소 + GitHub Pages | 무료, 자동화 쉬움 | 페이지 파일이 공개 저장소에 남아 버림 |
| 비공개 저장소 + GitHub Pages | 파일은 비공개 | 유료 플랜이 필요해 버림 |
| 게임 서버 Caddy에서 정적 파일 제공 | 항상 켜져 있음 | 게임 서버는 전원 담당만 하기로 해 버림. 한 번 적용했다가 되돌렸다 |
| Vercel API로 파일만 직접 배포 | 저장소 없이 파일만 올라감, 무료, 항상 켜져 있음 | 고름 |

## 바꾼 것

- 브리핑 템플릿·빌드 스크립트와 배포 스크립트는 Git에서 제외된 비공개 폴더에 둔다. 데이터와 만들어진 HTML도 Git 제외 폴더(`data/`)에만 있다. 공개 저장소에는 이 글만 남는다.
- 배포 스크립트는 Vercel 토큰을 실행할 때 Parameter Store에서 읽는다. 토큰은 파일이나 환경 변수에 저장하지 않는다.
- 배포를 production으로 바꿨다. 배포마다 생기는 주소는 Vercel 로그인을 요구하지만, 프로젝트 고정 주소는 로그인 없이 열리고 항상 최신 배포를 가리킨다. DM에는 고정 주소를 보낸다.
- 배포 뒤 고정 주소를 익명으로 받아 오늘 만든 `index.html`과 해시가 같은지 확인한 다음 DM을 보낸다.

## 확인한 것

- 실제 배포 1회: 상태 READY, 고정 주소 익명 응답 200, 받은 `index.html` 해시가 로컬 파일과 일치, 올라간 파일 3개(날짜 페이지, `index.html`, 헤더 설정).
- 소유자 DM 전송 1회 성공.
- 단위 테스트는 없다. 배포 스크립트는 실제 배포로만 확인했다.

## 틀린 지점

- 처음 DM에 배포별 주소를 보내 로그인 화면이 떴다. 고정 주소로 바꿨다.
- 게임 서버를 전원 전용으로 둔다는 원칙을 확인하기 전에 그 서버에 정적 경로를 추가했다. 바로 설정과 파일을 지우고 다시 적재했고, 기존 서비스 상태 확인 응답은 200이었다.

## 아직 모르는 것

- 매일 자동 실행: 게임 서버의 전원 봇이 정해진 시각에 개인 비서 서버를 켜고, 개인 비서 서버가 수집·빌드·배포·DM을 하고 유휴 종료로 꺼지는 흐름을 설계해야 한다.
- 여러 사용자: 친구도 채용 기능을 쓸 수 있게 하려면 사용자마다 포트폴리오, 데이터 폴더, 페이지 경로, DM 대상을 나눠야 한다. 아직 한 사람 기준이다.
- 고정 주소는 링크를 아는 누구나 열 수 있다. 검색 노출은 헤더로 막았지만 접근 제한은 없다.

## 셀프 인터뷰

**왜 저장소 대신 API로 파일을 올렸나요?**
페이지 내용이 개인정보라 공개 저장소에 남기면 안 됐습니다. Vercel 배포 API는 파일을 직접 받아서, 저장소를 거치지 않고 배포 서버에만 파일이 남습니다.

**배포가 끝났다는 것을 어떻게 확인했나요?**
배포 상태가 READY인 것만 보지 않고, 고정 주소를 로그인 없이 받아 오늘 만든 파일과 해시를 비교했습니다. 같을 때만 DM을 보냅니다.

**이 작업에서 배운 점은요?**
서버마다 역할을 먼저 확인해야 한다는 점입니다. 항상 켜져 있다는 이유만으로 게임 서버를 골랐다가 되돌렸습니다.
