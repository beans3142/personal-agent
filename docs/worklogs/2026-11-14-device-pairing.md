# 새 대비스 기기를 요청과 승인으로 연결하기

> 2026-11-14 · 커밋은 산출물 참고 · 코드 복사·Discord 명령 없이, 새 기기가 요청하고 연결된 기기나 대비스가 승인

## 무엇이 문제였나

새 폰이나 PC를 대비스에 연결하려면 Discord에 "폰 등록 이름"을 보내고, 받은 명령을 복사해 앱에 붙여 넣어야 했다. PC는 설치 명령까지 실행해야 했다. 소유자는 이 과정을 납득하지 못했다. "앱에서 기기 등록을 누르면 승인 대기가 뜨고, 이미 쓰는 대비스 화면이나 대비스에게 수락이라고 하면 연결되어야 한다"고 했다.

## 고를 수 있던 방법

| 방법 | 장점 | 고른 이유 또는 버린 이유 |
| --- | --- | --- |
| Discord DM 승인 버튼 | 구현이 작다 | 소유자가 Discord를 거치는 방식 자체를 거부해 버림 |
| APK에 비밀 키를 넣고 열면 자동 연결 | 단계가 없다 | 승인 없이 연결된다. 소유자가 "승인 대기 + 승인" 흐름을 원해 버림 |
| 새 기기가 요청, 연결된 대비스 화면이나 대비스 명령으로 승인 | Discord 없이 소유자가 보고 허락한다 | 고름 |

## 바꾼 것

- `agent/device_pairing.py`(중계 서버):
  - 새 기기가 `/pair/start`로 요청을 열면 4자리 번호를 돌려준다. 요청은 10분 뒤 끝나고, 한 번에 3개까지만 기다린다.
  - 연결된 PC·폰 앱이나 메인 에이전트만 `/pair/pending`, `/pair/accept`, `/pair/deny`를 쓸 수 있다.
  - 새 기기는 `/pair/poll`로 기다리다가, 승인되면 등록 정보를 한 번만 받는다.
  - 같은 이름의 기기가 다시 연결하면 예전 등록을 해제하고 바꾼다.
- 공용 화면(`desktop/ui/index.html`, PC 프로그램과 폰 앱이 같이 씀):
  - 연결 화면에 "기기 등록" 버튼과 승인 대기 번호를 넣었다. 기존 코드 붙여넣기는 접어 둔 "등록 코드로 연결"로 옮겼다.
  - 연결된 기기에는 "새 기기 연결 요청 · 이름 · 번호 [승인] [거절]" 카드가 뜬다. 8초마다 확인한다.
- PC 프로그램(`desktop/bridge.py`, `desktop/relay.py`)과 폰 앱(`MainActivity`, `Relay`): 같은 이름의 화면 호출(`pair_start`, `pair_poll`, `pair_pending`, `pair_accept`, `pair_deny`)을 구현했다.
- 메인 에이전트 도구 `device_requests`, `device_accept`, `device_deny`: "연결 수락해"로 승인한다. 요청이 여럿이면 번호를 달라고 한다.

## 확인한 것

- 관련 테스트 통과(전체 테스트는 돌리지 않음). `tests/test_device_pairing.py` 10개, `test_desktop_bridge` 11개, `test_desktop_relay` 37개, `test_pc_control` 23개, `test_phone_call` 29개, `test_device_nodes` 60개, `test_phone_alarm` 14개, `test_mcp_server` 27개, `test_progress` 11개.
- 중계 서버와 메인 서버에 배포했다. 공개 주소에서 `/pair/poll`이 응답했다.
- 서버 Android(ReDroid)에 새 APK를 깔고 1회씩 확인했다.
  - "기기 등록"을 누르니 승인 대기 화면이 떴다.
  - 실제 요청 경로로 "폰 연결 수락해"를 보내니 22.2초 만에 "폰 연결을 수락했어요"라고 답했다. 앱이 스스로 LINK ONLINE이 됐다.
  - 연결된 그 앱에 가짜 PC 요청을 보내니 "새 기기 연결 요청 · PC · TEST-PC · 번호" 카드가 떴다. 거절을 누르니 요청이 사라졌다.
  - 시험 등록은 해제하고 앱은 지웠다.

## 틀린 지점

- 처음에는 Discord DM 승인 버튼으로, 그다음에는 APK 안의 키로 자동 연결하려 했다. 소유자가 원한 것은 "대비스 화면 안에서의 승인 대기와 승인"이었다. 요구를 끝까지 듣기 전에 구현을 시작했다.
- 공용 화면 파일에 예전 작업에서 커밋되지 않은 루틴 화면이 남아 있었다. 누가 언제 만든 변경인지 확인하지 못해, 이번 연결 기능 부분만 골라 커밋했다.

## 아직 모르는 것

- 실제 소유자 폰과 PC 프로그램 화면에서는 아직 눌러 보지 않았다.
- 연결된 기기가 하나도 없을 때는 대비스 명령(Discord나 다른 입구)으로만 승인할 수 있다.

## 셀프 인터뷰

**아무나 요청을 보낼 수 있는데 괜찮나요?**
요청은 대기만 합니다. 연결된 기기나 대비스(소유자 명령)가 승인해야 등록 정보가 나갑니다. 번호를 함께 보여 줘서, 승인하는 사람이 자기 기기의 요청인지 맞춰 볼 수 있습니다.

**승인 전에 새 기기가 할 수 있는 것은요?**
없습니다. 대기 중인 요청 ID로는 상태만 볼 수 있고, 등록 정보는 승인 뒤 한 번만 나갑니다.

**왜 기존 코드 방식을 남겼나요?**
연결된 기기가 하나도 없고 대비스에게 말할 수 있는 입구도 없을 때를 위해서입니다. 화면에서는 접어 두었습니다.
