# 배민 가게 10곳을 모델 호출 없이 모은다

> 2026-11-07 · 커밋은 아래 산출물 참고 · 같은 초밥 질문 기준 가게 11곳, 모델 호출 4회, 입력 토큰 10.6k

## 무엇이 문제였나

"초밥 먹고싶은데 연 초밥집이랑 2만5천원 이하 메뉴 정리해줘" 요청에 대해 소유자가 원한 것은 다음과 같았다.

- 최소 10곳
- 가게마다 "메뉴 가격 / 메뉴 가격"처럼 한 줄로 정리
- 리뷰 이벤트 안내
- 배달 전문점(공유주방, 홀 없음) 걸러내기

그런데 모델이 화면을 직접 눌러 가게를 하나씩 여는 방식으로는 가게 3~5곳에 모델 호출 13~22회, 입력 토큰 38~90k가 들었다. 10곳을 보려면 호출이 60회를 넘어선다.

## 고를 수 있던 방법

| 방법 | 장점 | 버린 이유 또는 고른 이유 |
| --- | --- | --- |
| 호출 한도를 더 올리기 | 코드 변경이 적다 | 시간과 토큰이 가게 수에 비례해 늘어서 버림 |
| 배민 화면 탐색을 코드 도구 하나로 묶기 | 탐색 단계에서 모델 호출이 0회다 | 고름 |

## 바꾼 것

- `agent/baemin.py`의 `baemin_search(query, max_price, count)`가 하는 일:
  - 배민을 처음 화면부터 열고 검색어를 입력한 뒤 "배달" 탭으로 간다.
  - 목록의 가게를 차례로 연다. 가게 목록에서 별점, 최소주문, 배달팁, 예상 시간, 광고 여부를 읽는다.
  - 가게 화면에서 메뉴 이름, 구성, 가격 옵션 전부와 "주문 안내"의 리뷰 이벤트 문구를 읽는다.
  - "가게정보·원산지" 화면에서 주소와 편의시설을 읽어 홀 영업(`hall`)과 공유주방(`shared_kitchen`) 신호를 만든다. 이 버튼은 접근성 트리에 없어서, 배달/픽업 전환 버튼 위치를 기준으로 좌표를 계산해 누른다.
  - 장바구니 담기와 주문은 하지 않는다.
  - 200초 예산이 다 되면 `partial=true`와 함께 거기까지 모은 결과를 돌려준다.
- 지침:
  - 음식·가게 요청은 이 도구를 한 번만 쓴다(count=12).
  - 최소 10곳을 가게당 "머리 한 줄 + 메뉴 한 줄 + 리뷰이벤트 한 줄"로 정리한다.
  - 공유주방은 빼고, 홀 정보가 없으면 "홀 확인 안 됨"으로 표시한다.
- 주문 기본값을 지침에 넣었다: 일회용 수저·포크 받기, 리뷰 이벤트가 있으면 그 가게가 안내한 문구를 요청사항에 적기. 배민이 로그인돼 있지 않아서 실제 주문 화면에서는 확인하지 못했다.
- 휴대폰 스크린샷은 소유자가 화면을 보여 달라고 하거나 결제 직전일 때만 보낸다. 결제 승인 메시지에는 결제 직전 화면을 붙인다.
- 진행 표시는 기록 목록과 경과 시간을 지우고, 지금 하는 일 한 줄만 보여준다. 예: "⏳ 배민에서 가게 메뉴 모으는 중…"
- 시간 한도를 늘렸다:
  - MCP 도구 제한시간: 150초 → 260초
  - Hermes 실행 예산: 270초
  - 프로세스 제한: 310초
  - 단계 한도: 30회
  - 입력 토큰 상한: 160k

## 확인한 것

- 로컬 전체 테스트 734개가 통과했다. 배민 파서와 흐름 테스트 12개가 포함돼 있다. 이 테스트는 실제 화면에서 뽑은 노드 예시와 가짜 기기 상태 기계를 쓴다.
- 서버 실기기에서 도구만 따로 실행했다: 11곳, 190초.
- 서버에서 Hermes로 같은 질문을 실행했다(한 번 측정):
  - 가게 11곳이 요청한 형식으로 나왔다.
  - 모델 호출 4회, 도구 3회, 입력 토큰 10.6k, 235.4초.
  - 이전 방식은 가게 5곳에 22회, 65.6k, 134.7초였다.

## 틀린 지점

- 실기기 조사를 하는 동안 소유자의 실제 요청(16:16)이 같은 휴대폰을 쓰고 있었다. 내가 열어 둔 가게 화면 때문에 그 요청이 엉뚱한 가게를 답했다. 이후로는 조사와 QA 전에 진행 중인 요청이 없는지 확인한다.

## 아직 모르는 것

- 배민이 로그인돼 있지 않다. 그래서 배민클럽 배달팁(0원) 같은 회원 혜택이 목록에 반영되지 않는다.
- 전체 응답에 235초가 걸린다. 가게당 약 17초다.
- 홀 판정은 편의시설 항목에 의존한다. 편의시설을 적지 않은 가게는 "확인 안 됨"으로 남는다.

## 셀프 인터뷰

1. **왜 모델이 아니라 코드가 화면을 누르나요?** 같은 순서를 매번 반복하는 탐색이라서 판단이 필요 없기 때문입니다. 모델은 모인 결과를 정리할 때만 호출하고, 그래서 호출이 22회에서 4회로 줄었습니다.
2. **가게정보 버튼 좌표가 바뀌면 어떻게 되나요?** "상호명" 글자가 보이지 않으면 가게정보 없이 메뉴만 모읍니다. 그 가게의 홀·공유주방 판정은 "확인 안 됨"으로 남습니다.
3. **배민 화면이 업데이트되면요?** 목록 파서는 별점과 (리뷰 수)가 이어서 나오는 패턴에 의존합니다. 이 패턴이 바뀌면 가게를 0곳 찾게 되고, 도구가 그 사실을 오류로 알립니다.
