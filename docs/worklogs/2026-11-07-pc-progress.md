# 2026-11-07 PC 종료 응답: 취소 버튼과 같은 메시지 상태 갱신

요청: PC 종료 접수 답변에 실제 취소 버튼을 제공하고, 완료/실패를 새 답변 대신 기존 메시지에 반영한다.

## 구현
- 항상 켜진 전원 봇이 종료 작업별 Discord 상태 메시지 한 개를 저장하고 갱신한다. queued/dispatched/60초 대기/확인 중/취소 완료/실패/만료/연결 끊김/미확인을 구분한다.
- 취소 버튼은 owner 전용이며 PC 이름 대신 원래 job/node에 묶인다. 새 종료 요청이 있거나 확인 가능한 취소 시간이 지나면 기존 버튼으로 다른 요청을 취소하지 않는다.
- 큐에서 아직 전달되지 않은 종료는 직접 취소한다. PC가 접수한 종료의 취소는 별도 요청으로 전달하고 ACK를 확인한다. 지연된 취소는 원래 종료 유예가 끝나기 전에 만료한다.
- 상태 메시지 ID는 SQLite에 저장하고 봇 재시작 후 읽기 전용 관찰을 복구한다. 관찰 과정에서 종료 명령은 재전송하지 않는다.
- 자연어 MCP 경로도 신뢰된 채팅 위치를 전달해 같은 UI를 사용하며, 메인 Gateway의 중복 접수 답변을 생략한다.

## 한계
- 기존 PC 노드는 종료 예약 접수만 응답한다. Windows 종료 호출 성공이나 실제 전원 OFF의 독립적인 증거는 제공하지 않는다.
- 따라서 연결 끊김은 연결 끊김으로만 표시한다. 약 135초 동안 연결이 유지되면 종료 미확인으로 끝내며, 실제 종료 완료라고 주장하지 않는다.
- PC의 실제 종료/재시작, 실제 사용자의 버튼 클릭은 이번 QA에 포함하지 않았다. 모의 PC와 Discord 콜백으로 상태 전환/취소/권한을 검증한다.
- 범위는 PC 종료 작업이다. 일반 검색/카카오톡 등 모든 작업의 취소는 구현하지 않았다.
