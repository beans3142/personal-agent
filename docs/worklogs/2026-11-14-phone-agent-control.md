# 폰 화면 이미지를 에이전트에게 전달하고 공통 조작 도구로 실행하기

> 2026-11-14 · 관련 Python 테스트 114개 통과 · 실기기 확인은 새 앱 설치 후 진행

## 무엇이 문제였나

폰의 화면 정보는 글자와 버튼 목록뿐이었다. MCP 중계도 모든 도구 결과를 문자열로 바꿔서, 이미지 결과를 에이전트에게 전달할 수 없었다. 접근성 정보가 부족한 화면에서는 에이전트가 직접 보고 판단할 수 없었다.

잠금 해제 확인에서 폰은 연결되어 있었지만 잠긴 상태를 반환했다. 서버의 비밀번호 조회 기록은 없었다. 이전 앱은 입력칸을 찾지 못한 원인을 반환하지 않아, 입력칸 미노출과 잘못된 판별을 구분할 수 없었다.

## 바꾼 것

폰 앱의 접근성 캡처 기능으로 PNG 화면을 가져온다. `phone_screenshot`은 버튼 정보와 MCP ImageContent를 함께 반환하고, MCP 중계는 이 결과를 문자열로 바꾸지 않고 전달한다. 서버의 설치된 Hermes 소스에는 MCP 이미지 캐시와 모델 입력용 이미지 변환 경로가 있음을 확인했다. 실제 모델의 화면 이해 성공과는 구분한다.

좌표 스와이프와 길게 누르기를 추가했다. 기존 화면 읽기, 터치, 입력, 앱 열기, 스크롤과 함께 사용하는 공통 도구다. 앱별 버튼 순서를 추가하는 대신 에이전트가 현재 화면에 따라 행동을 고를 수 있게 한다. 폰 도구는 공개 채널 허용 목록에서 제외한다.

잠금 화면은 활성 창 하나뿐 아니라 접근 가능한 창들을 검색한다. 입력칸은 시스템 패키지와 입력 동작 지원 여부를 확인하고, 일반 비밀번호 속성 외에 알려진 시스템 입력칸 ID를 허용한다. 잠금 해제 요청은 Activity 창이 올라온 뒤 호출한다. 입력칸이 나타나지 않으면 위로 스와이프를 한 번 시도한다. 실패 시 단계와 창 패키지만 반환하며 비밀번호나 입력칸 내용은 반환하지 않는다.

## 확인한 것

관련 Python 테스트 114개가 통과했다. 이미지 MCP 결과 보존, 이미지 바이트 전달, 캡처 오류 표시, 좌표 제스처 전달, 공개 채널 제외, 폰 작업 프로토콜과 기존 도구의 회귀를 검사했다. 기존 Java 규칙 테스트와 잠금 해제 흐름 6개, 입력칸 판별 7개도 통과했다.

기능 커밋은 `7e5475a`다. 메인 서버의 폰 도구와 MCP 중계, 상시 중계 서버의 작업 허용 목록을 배포했다. 두 서비스 active와 새 도구 허용 설정을 확인했다. GitHub Actions의 APK 빌드가 통과했고, 설치 파일을 소유자 Discord DM에 첨부해 전달 응답을 확인했다. 에뮬레이터 기동 검사는 이 기록 시점에 진행 중이다.

## 아직 모르는 것

실사용 폰에서 캡처와 잠금 해제가 성공하는지는 새 앱 설치 후 확인해야 한다. Android 보안 창은 캡처를 거부할 수 있으며 오류를 그대로 전달한다. 서버가 이미지를 전달하는 것만으로 모델이 화면을 보고 올바른 조작을 했다고 주장할 수 없다. 배달 주문이나 카톡 사진 전송의 완료도 아직 확인하지 않았다.

## 셀프 인터뷰

**다른 앱을 쓸 때마다 APK를 바꿉니까?**
공통 도구로 가능한 화면 탐색과 조작은 서버 에이전트의 판단으로 수행합니다. 캡처나 제스처 같은 실행 기능 자체의 결함은 앱 수정이 필요합니다.

**잠금 해제의 실제 원인을 확정했습니까?**
아닙니다. 이전 버전의 진단 부족으로 실기기에서 어떤 창이 보였는지는 모릅니다. 확인된 단일 창 검색과 엄격한 판별 조건을 수정하고 실패 단계 진단을 추가했습니다.

**이미지를 모델에 전달할 수 있습니까?**
MCP 결과가 이미지 형식을 유지하는 테스트는 통과했습니다. 실제 폰 이미지에 대한 모델 응답은 설치 후 별도로 확인해야 합니다.
