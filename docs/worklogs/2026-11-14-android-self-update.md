# APK를 직접 받아 설치하는 대신 앱이 새 버전을 확인하기

> 2026-11-14 · 관련 Python 테스트 119개 통과 · 실기기 자동 설치는 확인 전

## 무엇이 문제였나

폰 기능을 고칠 때마다 소유자가 Discord에서 APK를 받아 다시 설치해야 했다. 서버 배포와 별개로 앱 배포를 수동 전달에 의존했다.

## 바꾼 것

메인 브랜치의 APK 빌드와 에뮬레이터 기동 검사가 모두 성공하면 CI가 기존 중계 서버에 파일을 게시한다. 게시 권한은 별도 비밀 토큰으로 분리했고 서버에는 토큰의 해시만 둔다. 다운로드는 등록된 폰만 허용한다. 버전 후퇴와 같은 버전의 다른 파일 게시를 거절한다.

폰 앱은 연결 시작과 유휴 대기 뒤에 업데이트를 확인한다. 확인 간격은 15분이다. 새 APK의 SHA-256, 패키지 이름, 버전, 설치된 앱과의 서명 일치를 확인하고 Android PackageInstaller로 자기 자신을 업데이트한다. 폰 작업 직후 2분간은 설치를 미룬다. 필요한 경우 설치 허용 설정이나 설치 확인을 알림으로 안내한다. 설치 완료 후 기존 연결 서비스가 다시 시작되도록 기존 패키지 교체 수신기를 사용한다.

## 확인한 것

관련 Python 테스트 119개가 통과했다. 추가 테스트는 게시 파일 검증, 버전 후퇴 방지, 동일 빌드 재게시, 게시자·폰·PC의 권한 분리와 파일 다운로드를 다룬다. Java의 업데이트 판별 7개와 기존 규칙·잠금 해제 테스트도 통과했다.

중계 서버 배포 후 인증 없는 업데이트 조회가 HTTP 403임을 확인했다. 초기 배포에서 게시 토큰 해시 파일이 서비스 계정에 읽히지 않아 서비스가 재시작을 반복했다. 해시 파일 읽기 권한을 바로잡고 서비스 active 및 실제 HTTP 응답으로 복구를 확인했다. 초기 active 상태 한 번만으로 정상이라고 판단하지 않았다.

## 버전 표시와 직접 확인

초기 버전은 현재 버전과 상태 표시가 없어 업데이트가 적용됐는지 소유자가 판단할 수 없었다. 앱 상단에 현재 버전을 표시하고, 설정에 현재·최신 빌드, 진행 상태, '지금 업데이트 확인' 및 설치 허용 설정 버튼을 추가했다. 앱이 화면으로 돌아올 때도 즉시 확인한다.

설치된 버전은 Android PackageManager에서 읽어 인증된 서버 요청으로 보고한다. 서버의 등록 폰별 실행 버전 기록이 바뀌는 것을 적용 확인의 근거로 삼는다. APK 게시 완료나 소유자의 설치 시도만으로 실제 실행 버전이 바뀌었다고 판단하지 않는다.

업데이트 확인을 폰 작업 유무와 분리했고, 실행 중에는 1분마다 확인한다. 작업이 있으면 설치만 미룬다. 실패한 조회로 15분간 재시도가 막히던 문제도 수정해 실패 시 짧은 간격으로 재시도한다. 서버의 버전 보고 저장 경로를 HTTP 테스트로 확인했다. 이 변경의 실제 폰 버전 보고는 배포 후 확인해야 한다.

## 아직 모르는 것

기능 커밋 `a449d9e`의 CI 빌드·에뮬레이터 기동 검사·자동 게시가 모두 통과했다. 중계 서버의 게시 응답에서 버전 22와 APK 크기 139,947바이트를 확인했다. 이 APK를 소유자 Discord DM에 첨부해 전달 응답을 확인했다. 이 결과는 배포 경로의 검증이며 실기기 자기 업데이트 성공 검증은 아니다.

사용 중인 Galaxy에서 확인 창 없이 설치되는지는 실기기에서 확인해야 한다. Android는 자기 업데이트에도 조건이나 기기 정책에 따라 사용자 확인을 요구할 수 있다. 업데이트 기능이 없는 기존 앱에는 새 버전을 한 번 직접 설치해야 한다. 이후에도 설치 확인이 필요하면 파일을 따로 받지 않고 앱 알림에서 진행한다.

## 셀프 인터뷰

**무조건 조용히 설치됩니까?**
아닙니다. Android 공식 자기 업데이트 조건을 사용하고, 사용자 확인이 필요한 응답도 처리합니다.

**파일을 다른 앱으로 바꿔치기할 수 있습니까?**
다운로드 후 패키지·버전·해시·서명을 확인합니다. Android 설치 관리자도 서명을 검사합니다.

**작업하다가 업데이트하면 어떻게 됩니까?**
최근 폰 작업이 있으면 미루고, 다운로드 중 작업이 시작됐는지도 설치 직전에 다시 확인합니다. 시스템 설치 확인을 직접 누르는 순간까지 모든 경쟁 상황을 검증한 것은 아닙니다.

## 버전 25 배포 확인

버전 표시·직접 확인 버튼의 커밋은 806c74f다. CI 빌드·AOSP 기동 검사·자동 게시가 모두 통과했다. 에뮬레이터의 실제 실행 화면에서 상단 v0.1.25 · 25 표시를 확인했다. 관련 Python 119개와 Java 규칙 테스트가 통과했다.

소유자는 자동 설치 허용을 켰다고 알렸다. 이후 서버의 실행 버전 보고는 비어 있었고, 폰 화면 요청도 이전 실행기의 잠금 실패 형태로 돌아왔다. 실기기 적용을 주장하지 않았다. 버전 25 APK를 소유자 DM에 대체 설치 파일로 전달했다. 실기기 자기 업데이트 완료와 잠금 해제, 카톡 전송은 아직 확인하지 못했다.
